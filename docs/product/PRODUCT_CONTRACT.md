# ZeroAgent 产品契约

本文定义重构和合并 LiveAgent 上游时必须保留的产品结果。只要产品结果、安全属性、支持端
以及回归测试保持一致，具体实现可以演进。

## 产品身份

- 产品名称为 ZeroAgent，原生应用标识为 `top.usa0.zeroagent`。
- USA-Zero 为 ZeroAgent 提供账户、权益、托管 API Key、分组和模型服务。用户界面不得将其
  显示为 SUB2API、ZeroBox 或 LiveAgent。
- 面向用户的服务地址为 `https://agent.usa0.top`。
- 工程记录可以说明上游来源，但 ZeroAgent 界面和公开发布说明必须描述 ZeroAgent 产品。

## 运行模式

- Cloud Chat 运行于托管 WebUI，可以使用 USA-Zero 托管的模型能力；不得提供仅桌面端可用的
  本地执行、代理、终端、文件系统或原生更新控制。
- 设备 Agent 是经过认证并由用户明确选择的 ZeroAgent 桌面设备，可以执行本地工具和访问
  本地工作区；远程设备选择必须明确并受账户隔离。
- 桌面端的本地功能不依赖浏览器控制界面也应保持可用。
- Android 端嵌入受支持的 WebUI，安全完成 USA-Zero OAuth，使用平台安全设施保存凭据，并
  遵循 ZeroAgent 更新通道。

## 账户、设备与数据

- USA-Zero OAuth 是唯一账户登录契约。每种 ZeroAgent 应用形态使用一个稳定 OAuth 客户端；
  重复登录只创建或续期会话，不得重复创建已授权应用。
- 账户数据、对话、工作区、设备可见性、执行租约和撤销操作必须按认证账户隔离。
- 设备身份在一次安装周期内保持稳定；会话可以独立过期或撤销而不改变设备身份。在线状态
  必须受心跳和过期机制约束，不能无限期表示设备在线。
- Secret 和托管 API Key 不得写入日志或公开产物。托管密钥默认遮罩，显示或复制前必须完成
  最近一次 USA-Zero 二次认证。
- 对话和上传文件的存储必须按账户隔离；存储路径发生变化时需要文档和迁移，禁止静默丢失
  用户数据。

## 发布与运维

- `0xHyperia/ZeroAgent` 根据其仓库可见性发布完整源码和运维产物；用户可下载的二进制同时
  发布到 `USA-Zero/ZeroAgent`，不得附带源码归档或内部运维信息。
- 公开 Release Notes 只描述用户可感知的 ZeroAgent 变化，不得提及私有源码拓扑、Gateway
  镜像、凭据、内部部署或未公开基础设施。
- Gateway 生产镜像必须不可变并按审核通过的 digest 部署。就绪检查必须验证必要依赖，而不
  只是确认进程存活。
- Desktop、Android、Gateway、生产部署和双仓库发布流程均属于产品契约，不能在上游合并时
  作为可选清理项删除。

## 变更规则

修改实现决策时，必须记录原因、迁移与回滚影响、安全审查、受影响端和回归测试。修改硬性
产品不变量需要明确的产品决策记录和用户批准；仅有“上游这样实现”不能作为修改理由。
