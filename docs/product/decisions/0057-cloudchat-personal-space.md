# ADR 0057：CloudChat 个人资料空间

- 日期：2026-10-30。
- 状态：按用户要求本地实施，不推送、发布或部署生产。
- 范围：CloudChat Web、嵌入 Web 的 Android 和 Gateway；默认 Desktop/设备工作区保持。

用户要求资料空间作为每位用户的工作资料与产出中心，具有容量限制，并沿用既定的双层导航、
轻中性表面、统一菜单/提示、响应式布局。参考用户提供的 ChatGPT 资料空间与豆包云盘截图，
使用现有组件及真实能力，不引入独立文档平台、运营后台、协作权限或无实际功能的模板入口。

原件仍由 `zeroagent_cloud_files` 持有，产出由不可变 artifact version/family 持有。
新增 `zeroagent_cloud_space_metadata` 只保存账户范围的名称、文件夹、收藏、回收站和版本，
不复制原件/解析正文、不增加第二份成果权威。产出按 family 展示最新版本，版本预览和引用仍
绑定明确的 version ID。已有会话、文件和成果立即通过读取投影可见，不回填、清除或重写数据。

独立上传允许文件没有来源会话。仅取消原有文件表的 conversation_id 非空约束，新增原件可以
为 NULL；现有会话关联值不变。服务端仍从当前 session 取得账户，客户端不能指定 user_id，
若传入会话则继续验证归属。不为上传或浏览创建隐藏/空白会话。原件校验、对象归属、解析、
下载、待确认上传和删除意图继续走原服务。浏览器未知写结果不能自动重试。

文件夹目前为单层、最多100个；非空文件夹不能移入回收站，避免隐藏子项。
名称为整理元数据，原件文件名与历史引用保留。收藏、移动、重命名和回收站操作采用读取版本
CAS，并按账户串行化，过期请求显式冲突。回收站是可恢复的整理状态，不撤销旧对话引用，
账户快捷选择列表排除回收站条目；彻底删除仍使用原件/成果预览中的明确确认及原服务清理。
回收站和失败/待核对/待删除的对象均继续占用额度，远端确认删除后才释放。

新增只由服务端读取的账户容量覆盖表 `zeroagent_cloud_space_limits`，没有面向普通用户的额度
修改接口。默认沿用上传原件256 MiB、产出版本256 MiB的现有子限额，合计512 MiB；单件32 MiB，
两类各最多500项/版本。更低的账户总额可由运维权益配置设置。两类预留共用账户事务锁并检查
总额，同时保留原子限额，避免并发上传与产出越界。UI展示总额和两类明细，不暗示额度可互换。
此处为当前工程默认值，不决定未来商业套餐。提高限额时必须同时调整容量查询、分页与资源预算。

资料空间全库名称搜索、分类、排序在服务端执行。当前账户的原件和版本本身分别有500项硬限额，
因此使用有界元数据快照聚合，不读取正文；每页50项。筛选不是浏览器仅过滤首屏，也不是正文语义检索。
未来提高上限需改为数据库查询及稳定游标，而不能继续扩大内存扫描。

页面导航不重建原对话编辑器或重设模型/执行权限。资料空间首次打开后按账户保留挂载，隐藏时
退出可访问树；独立上传不因切换对话被取消。退出/切换账户时中止请求和清理图片对象URL，迟到
结果不能进入新账户。引用先重新获取规范元数据、校验可用状态及原8项上限，再返回同一草稿。
新建文档/表格/演示文稿只准备用户可编辑的任务，显式发送后走同一Go工具循环及正式成果存储。
文件夹是资料组织，不代表E2B目录，当前新产出默认进入账户空间，不假称自动写入所浏览文件夹。

现有备份按实际schema导出表，新增元数据/额度表随同保存；回收站原件没有服务端删除意图，
继续纳入原件备份。撤销源码不清理新增表或原件；旧客户端未支持独立上传，不能承诺读取所有新行。
没有旧产品自动迁移、供应商/密钥变更或对外共享授权。

验证包含 Memory/PostgreSQL CAS与账户隔离、空会话独立上传、跨页搜索、额度及预留、
回收站/恢复、原文件/成果协议、客户端迟到响应/未知结果、组件交互、Web类型/构建/边界，
以及生产bundle在桌面、320/390px手机、深色和实际菜单的浏览器检查。
真实S3/E2B/模型内容质量与Android真机不以本地合成夹具代替，实际范围记录于 design-qa.md。
