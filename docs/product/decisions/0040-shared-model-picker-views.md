# ADR 0040：统一模型选择视图

- 日期：2026-10-27（Asia/Hong_Kong）
- 状态：按用户要求统一聊天与高级设置的模型选择

聊天及设置中的文本模型选择共用 `ModelPickerContent`、搜索、折叠和路由分组逻辑。
每次打开默认折叠全部分组，包括当前模型所在分组；搜索临时展开匹配结果，不覆盖手动展开状态。

保留按分组选择模型，并新增按实际模型厂商分类的视图。厂商按模型 ID 识别，不把平台分组的
协议类型当成厂商。同一精确模型 ID 在厂商下合并展示，先选择模型，再明确选择可用分组/密钥；
点击模型、返回或切换视图不会提前改变当前模型。最终仍提交原选项的完整 provider/model 值，
不创建供应商、不更换账户或地址，不按协议类型猜测、回退到另一密钥。

视图偏好只在本地保存枚举，不保存账号、模型或密钥信息。标题、Commit 和澄清模型使用同一
套选择逻辑及跟随当前模型入口。故障转移队列仍是供应商选择，通过显式 provider 模式保留其
直接选择语义，不显示厂商/模型视图；候选及已配置队列只展示名称，不展示服务地址。
上下文、能力、模型别名、键盘操作和编辑入口继续保留。

刷新操作位于模型搜索工具栏，不占用返回栏或推理设置页。弹层高度同时受实际可用空间约束，
列表使用可收缩的单一滚动容器并保留底部内边距，避免滚动末尾的模型被外层裁切。
桌面端主会话和分屏会话都传入刷新回调及加载状态；桌面会话绑定将两者设为必填，防止入口漏接。

不修改持久化数据结构或已有选择，不迁移或清理用户数据。撤销只恢复原先两个选择器。
验证包括默认折叠、厂商识别、同模型多分组、先模型后分组、偏好共享、清空选择、供应商模式、
键盘导航、慢保存/快速切换竞态和移动控件回归，以及三端类型检查与 Desktop/WebUI 构建。
界面效果由用户手动确认。
