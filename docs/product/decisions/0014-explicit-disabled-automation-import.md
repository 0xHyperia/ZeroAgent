# 0014：显式导入旧版自动化并保持关闭

- 状态：已采纳，实施及验证中
- 范围：桌面 ZeroAgent v0.x 配置库到 v2 当前 profile；Android 不执行桌面迁移

旧版定时任务和钩子存于 `.zeroagent/config.sqlite`。账户切换不应自动认领这些全局记录，
也不应在导入完成时执行旧命令、HTTP 请求或模型任务。

在现有“导入旧版配置”的确认预览中列出任务和钩子的数量。指纹绑定当前目标空间以及
配置、任务、钩子的内容。确认后的原始自动化定义保留在 Native，前端只接收数量；导入
完成前由当前空间的 AutomationStore 在同一 SQLite 事务中补充缺少的 ID，全部新记录
强制关闭，并经过当前 schema 校验。现有记录与用户编辑不覆盖，重复导入不增加修订号。
正常变更通知仅在事务提交后发出。

保留任务的 cron、剩余次数、模型引用、工作目录和自定义 HTTP 凭据。用户需要在启用前
确认模型、目录与当前空间的时区；缺失的 Provider 不从其他账户补取。托管 Provider
不导入；若其明文凭据被复制到其他配置、脚本或 HTTP Header，拒绝该来源。当前进程
的托管凭据保护同样应用于自动化内容。这不代表能识别任意编码后的凭据。

不迁移旧运行记录、待执行队列、执行租约或调度器状态。原库只读。配置与自动化属于
不同存储，整体不宣称原子；自动化内部事务失败全部回退，已有配置写入保留并重载，
迁移记录标记失败，重试仅补缺项。迁移记录只写指纹和数量，不写脚本、请求或密钥。

后续按用户选择及 ADR 0015：旧自建服务商只进入独立归档表，与本次任务/钩子共用 Native
事务。导入任务引用这些模型时，Native 拒绝启用、手动执行及 prompt 排队，直到用户改选
托管 Provider；不因通用界面过滤而静默丢弃归档。

回归覆盖：原库字节不变、预览不返回自动化正文、内容变化使指纹失效、账户 A/B、
关闭状态、无可执行队列、重试保留编辑、跨域事务回退、托管凭据别名及完成记录约束。
