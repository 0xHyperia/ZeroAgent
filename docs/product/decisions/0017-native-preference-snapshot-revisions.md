# 0017：原生偏好的快照版本与批量提交

> 后续：生产桌面保存已切换到 ADR 0019 的规范批量 IPC，旧 settings_save_native_batch 不再注册。本文的原生工作副本、SQL 版本检查与原子提交继续作为其内部实现。

- 状态：部分实施；原生偏好批量保存已接线，统一后端/备份/设备协调仍未完成
- 关联：ADR 0010、0016

原生设置此前按系统、SSH、远程连接、记忆、故障转移和 STT 分别保存。复合编辑必须在
同一读取版本下提交，不能把多个使用同一旧版本的请求并行发送，或通过保存前重新读取
最新版本为旧编辑补上新版本。

配置库维护随机命名空间与递增序号，七张原生偏好表的 INSERT/UPDATE/DELETE 触发器都会
推进序号；SSH 项目关联包含在内。旧的私有迁移/恢复写入和另一 SQLite 连接因此也会使
旧快照失效。设备运行状态、SSH known-hosts 和 WebDAV 上传状态不推进偏好版本。
读取偏好与版本使用同一 SQLite 读取事务，版本只随实际读取的文档返回。

新 `settings_save_native_batch` IPC 验证 profile 与可移植凭据边界，在内存工作副本完成
输入验证和既有密钥保留逻辑，再在短 IMMEDIATE 事务内重新核对版本并替换触及的表。
任何校验、SQL 或版本错误都不能部分提交。系统代理/设备连接的提交后刷新失败返回
“配置已保存”的警告及新版本，不把已提交配置伪装成未提交。旧的无版本偏好保存 IPC
不再注册；私有迁移和备份工具暂时保留，尚未构成统一写入协调器。

前端一个复合编辑只调用一次批量 IPC。连续排队编辑只有在完整原生偏好基线等于本窗口
上次成功提交的预期结果时，才继承那次提交的新版本；其他编辑保留自身读取版本。
发生版本冲突后重读当前配置，队列中的旧快照继续受原版本约束。STT 独立表单绑定打开
时的读取版本，接受已保存结果后更新版本，不再让主设置层重复提交已保存的 STT 文档。

新版本表不是可移植配置正文，也不导出原始凭据。已有备份、迁移和归档格式保持；旧
自建服务商继续只用于归档、导出与回退，不开放其模型。回滚到旧程序不依赖此版本表。

本决定只覆盖原生偏好域。K-brain Provider/MCP/提示词、公开 HTTP 配置写入、规范备份
采集/恢复/补偿、WebDAV 和设备 Gateway 的持久化后 ACK 仍需接入统一边界。不得把本
域的 CAS 或触发器当作整个配置体系已具备一致快照与恢复隔离。定向结果见同步报告；
真实原生 UI、移动端及最终冻结全矩阵仍待验收。
