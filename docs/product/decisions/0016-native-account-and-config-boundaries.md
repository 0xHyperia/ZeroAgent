# 0016：原生账户会话与配置写入边界

- 状态：部分实施；Desktop 原生会话、账号/密钥/设备与 WebSocket 生产入口已接线并完成定向测试；配置统一写入、全链路绕过检查与跨平台真实验收仍未完成
- 范围：ADR 0004、0007、0008、0010 的剩余边界

当前模型代理已把 K-brain 使用的托管密钥替换为能力凭证，Desktop 账户消费者也已切到 Native 遮罩接口；其余端与配置路径仍需完成统一验收。
另外，锁定后端没有配置 CAS，多域恢复的补偿可能覆盖独立写入。仅在前端隐藏密钥、
增加密码布尔结果或只给 Native 恢复加锁，都不能完成这些边界。

原生账户会话的方向：

- Desktop 已把 PKCE 授权码交换、刷新和 OS 安全存储移入 Native，渲染层只取得不透明
  会话句柄与账户摘要；返回原始 token 的旧兼容 IPC 不再注册。其余端和剩余路径继续按
  下述边界适配，不能将已完成的桌面入口视为整个跨平台边界完成。
- Native 向固定 USA-Zero 来源验证 current-user，再派生 profile；profile 激活和设备凭据
  操作不能信任渲染层提供的 scope。切换、退出和过期按会话代次取消旧请求和模型能力。
- 账户 API 采用固定来源和端点白名单；密钥列表与创建响应只返回遮罩摘要，Native 内取得
  模型密钥并绑定代理。不能让通用账户代理重新返回原始密钥或认证 token。
- 明文显示/复制使用 Native 或 Gateway 内的当前会话、指定 key ID 和实时密码证明；不接受
  客户端传入的“已验证”布尔值。证明不得替换 OAuth 会话，完成前后均重查身份代次。
- WebUI/Android 通过账户化 Gateway 做相同的密钥遮罩与授权；模型发现和 Cloud Chat 在
  服务端按已认证账户解析 key ID，不能依赖浏览器持有原始密钥。

配置写入的方向：

- 渲染层和设备 Gateway 只取得 Native 管理的 K-brain 入口；真实后端 token 留在 Native。
  旧直连入口必须同时关闭，避免出现两套写入路径。
- 正常配置变更、导出采集、恢复与补偿共享 profile 内的写入边界；模型运行、历史和文件
  传输保持各自的权限、取消与流式语义，不以全局阻塞模型执行代替配置协调。
- 设置读取携带可验证的配置版本，过时写入明确拒绝并重载。复合设置保存需要一次受控的
  批量操作，不能让同一版本的并发分域请求互相冲突，或在排队后应用旧的完整 Provider 列表。
- 恢复在同一边界内采集回滚副本、修改并补偿；原生偏好及后台同步也必须遵守该边界。
  迁移记录仍不包含配置正文或凭据，既有原始数据与私有回滚副本继续保留。

实施顺序先建立原生会话及 profile 证明，再切换密钥数据路径，最后统一配置写入与版本协议。
每一步保留可执行的双账户、退出/刷新竞态、绕过读取、真实锁定后端和回滚夹具；仅在
这些路径均接入且通过后，才可删除 ADR 0008/0010 中对应的未完成项。新增 HTTP 中介必须
验证 SSE、丢失 ACK、取消、大文件、重启与受支持平台，不能只凭配置单元测试宣称完成。

## 历史第一步：profile 身份证明

本节与下节保留阶段记录；当前生产入口以最后的“Desktop 生产接线”一节为准。

`kbrain_backend_activate_profile` 不再接受账户 scope 作为权限依据。存在登录凭据时，
Native 向构建时固定的 USA-Zero HTTPS 来源读取 `/api/v1/app/me`，兼容旧密码会话时使用
`/api/v1/auth/me`。只有有效、活跃且 ID 可被各端精确表示的账户才派生存储 scope；无效
凭据或网络失败明确报错，不降级到离线 profile。没有会话时仍可明确打开离线本地空间。

验证 HTTP 不跟随重定向，不发送 Cookie 或浏览器 Origin；完整响应有 10 秒期限和 1 MiB
上限，错误不回显凭据或响应正文。验证请求开始时分配代次，旧响应即使晚于新请求失败
也不能激活账户。已有启动取消、首次绑定后切号重启和设备凭据范围检查继续使用该派生身份。
前端只发送当前凭据快照并核对返回时登录状态；scope 取自 Native 响应，绝不由前端 user ID
选择目录。前端原生启动期限为 90 秒，覆盖身份验证与 Windows 60 秒有限启动预算。

这一步不把浏览器 localStorage 变成安全存储，不提供持续的原生会话撤销管理，也没有完成
密钥遮罩、二次认证或配置 CAS。旧纯前端 scope 工具仅用于显示和兼容测试，不再决定
Native 激活。新编译、双账户竞态及原生 UI 证据以同步报告为准。

### OAuth 来源和失效登录的补充

桌面 PKCE 流程也只接受构建时固定的 HTTPS 根来源；授权页由固定 `/oauth/authorize` 与
编码后的 request ID 组成，不使用响应中的任意 `authorization_uri`。授权请求、换码和
current-user HTTP 不跟随重定向，分别有 10 秒期限和 1 MiB 响应上限。返回前检查 Bearer
令牌、正数有效期、profile:read 与活跃账户。错误不透传服务端正文；PKCE、state、稳定
client ID、loopback 回调和 5 分钟用户授权等待继续保留。完整浏览器 OAuth 仍需真实验收。

身份接口明确返回 401/403 时，Native 给出固定认证错误；前端停止重复尝试该凭据，且
只清除仍与请求快照一致的登录态。启动页提供“重新登录”操作，用户点击后重新启动选择
流程。网络错误保留登录态，旧账户请求被拒绝不能清除新账户；失败请求本身从不激活
离线目录。该恢复界面不是持续的 Native 会话管理或撤销验收。

当前本地 USA-Zero 服务端的 app execution step-up 仅授权 `execution_target_switch`，
`IssueAuthorized` 根据既有 execution:authorize scope 签发；它没有为本次操作重新校验
密码。后续密钥复制不能把这个执行目标证明当作 ADR 0004 的实时密码证明，也不能
据此宣称二次认证边界已完成。服务端源码仅只读核对，线上实际协议仍须凭据验收。

## 历史准备阶段：原生会话核心

新增 `services/account_session.rs` 及真实本机 HTTP 夹具。核心持有原始 token，公开摘要
仅包含随机句柄、经验证的用户字段及 scope；动态 JSON 字段按类型白名单截取，并隐藏
已知 token 的反射值。OS 保存记录不含公开句柄和用户资料，恢复时重验服务端账户及
保存的 user ID。暂时仍由原有生产账户客户端工作，不能把本模块测试作为 token 已移出
渲染层、旧 IPC 已关闭或密钥边界已完成的证据。

刷新单独合并并发请求，保留同一 Native 句柄，重新验证账户后才提交轮换值。HTTP 不
持会话写锁；持久化与会话提交共享短临界区，旧刷新/授权响应无法覆盖新账户或恢复
已退出会话。系统存储失败明确报错，失败清除后当前进程不重读旧记录；跨重启时的存储
故障恢复仍需生产入口和 UI 验收，不能据此声称失败注销已成功持久化。

服务端本地源码确认每次授权码交换会更新安装的 session ID 和 token family。因此
原生授权码交换需要串行，浏览器授权等待保持独立；换码前检查授权代次，过期结果在
新换码开始前撤销。退出同时尝试撤销 access 和 refresh，迟到的刷新结果也撤销，避免
已消费的旧 refresh token 无法定位会话族。所有 HTTP 仍有独立 10 秒期限。该行为尚未
接到桌面 PKCE 生产命令，线上会话族语义也仍需真实授权验收。

系统存储使用已锁定的 keyring 3.6.3 原生接口。发布版已有单实例保护；debug 跳过该
保护，因此新 vault 的 debug 名称加可执行目录摘要，隔离已安装正式版。当前进程内
事务不能冒充任意并发进程的 vault CAS；同路径多 debug 实例仍需在集成时处理/验收。
Windows 测试只使用随机命名的短期 fixture 条目，读写后删除，不访问真实账户条目。

下一步按同一边界接入 Desktop OAuth、启动、账户 HTTP、设备注册及 Protobuf WebSocket
握手；完成密钥遮罩、Native 内绑定及密码证明后，一起关闭旧 token/secret 通路。不能
通过前端假 token 或测试 stub 保留旧运行通路并宣称完成。

## Desktop 生产接线

Desktop OAuth 命令现在仅返回 Native 会话摘要。恢复、一次性旧 localStorage 导入、刷新和退出由
Native 及 OS vault 管理；导入成功后删除五项旧认证存储。profile 激活只接受不透明句柄，
不接受渲染层 access token、auth kind 或自选 scope。新登录提交后，既有 profile 的进程先
退出重启再向新窗口暴露摘要；前端也拒绝迟到的启动、HTTP、密钥和设备结果。

账号 HTTP 固定来源与路由白名单，密钥列表和创建响应经过遮罩，并清除当前 token、已知
托管密钥的字符串及 JSON 键名反射；模型绑定只接受受验证账户拥有且启用的 key ID。
指定密钥复制由 Native 读取当前账户邮箱并实时验证密码，验证前后重查当前句柄和密钥归属，
临时密码登录不会覆盖 OAuth。OAuth 账户的邮箱/密码管理转到固定 USA-Zero profile 页面；
昵称和头像继续走 app profile 接口，旧密码会话仍可使用原有账号安全路由。

设备注册、读取身份和轮换返回设备摘要，真实凭据在 Native 内读写和激活。桌面控制 HTTP
与浏览器角色的 Protobuf WebSocket 经固定 Gateway 来源；初始 hello 的真实 JWT 只在
Native 注入，保留服务端选择租约，拒绝角色、句柄或设备凭据混用。前端仅传递二进制数据
和句柄，账号结束时关闭相关连接。通用资源代理拒绝账号来源及重定向到账号来源，防止
重新登录或读取原始密钥绕过专门接口。

会话提交与清除同步使旧 profile 权限标记失效；后端冷启动和 Native 命令直接检查该标记，
不能等待异步结束事件才拒绝旧请求。运行时结束事件还停止后端、Gateway、本地终端及托管
进程，自动化的新触发检查 profile 权限。OS 删除失败保留可重试句柄，阻止恢复和离线激活，
成功重试后才发布可重新进入的退出事件。故障时没有宣称注销已持久化成功。

当前定向测试覆盖本机账号 HTTP、系统 vault fixture、两种握手编码、资源重定向及前端 IPC
竞态；不能当作真实 Gateway WebSocket、真实 OAuth、运行中自动化取消或跨平台 UI 验收。
已知原始 K-brain token 入口、配置写入/CAS、全部导出别名、跨进程 debug vault 竞争及刷新后
vault 写入失败的完整恢复仍需继续处理。不得据此把整个账号/密钥信任边界或同步标记为完成。

### 生命周期补充验证

退出菜单等待原生退出 Promise，失败时保留错误提示与重试入口，不把失败当成完成。请求
进行中合并连续点击，接口类型要求调用方返回 Promise。真实 React/Base UI DOM 测试验证
失败后账号摘要仍在、重试成功才关闭菜单，内部错误正文不直接展示。

Native WebSocket 把网络转发与事件投递分开，仍由同一个生产函数执行。取消信号和会话
结束信号在整个转发 future 外等待，因此对端停止读取导致的 send 阻塞也能被取消；结束
时的 Close 刷新最多等待 100 毫秒。注册项带独立连接代次，旧任务清理不能删除替代连接。
新增真实本机 TCP/WebSocket 夹具覆盖浏览器和终端首帧、仅 Native 注入的 JWT、受保护值
反射、退出断连、阻塞写入取消和旧账号不能关闭新账号连接。六项握手/传输与二十二项
会话/API 测试通过。它们不是已部署 Gateway 与真实账户的完整验收。

完整库基线为 1,194 通过、0 失败、5 按原规则忽略，先于上述取消补充；本轮 fresh 结果
单列。全量前端发现的旧密码断言已适配 Native key ID/password 授权，继续禁止复制桌面
预载原始 key；WebUI 原有密码验证仍检查。失败批和新增菜单 DOM 共 773 通过、1 环境
跳过，该跳过的记忆/Skills 真后端用例随后用工作区内隔离目录补测通过。最终发布仍需
冻结全部后续改动后的完整矩阵，不能将这组分批及定向结果描述为最终同步通过。

### 新凭据清理与 Native 可移植配置守卫

新授权码交换已经收到凭据、但身份验证、响应契约或 vault 保存失败时，Native 在释放换码
串行边界之前尝试撤销刚签发的凭据。已有会话的恢复失败不走这条新授权清理路径，避免
因暂时网络或存储故障撤销原有授权。密码证明收到的临时 access/refresh 同样在证明成功、
失败或账号切换后尝试清理；没有可撤销 refresh 的 MFA challenge 仍依其自身期限失效。
清理沿用固定来源及有限 HTTP 期限，不能将网络失败时的尝试描述为已获服务端确认撤销。

Desktop 的 K-brain 状态现在关联同一个 Native 账号核心。规范备份、恢复、旧配置归档等
已有守卫入口会检查当前句柄，以及该进程已知的全部托管 key（含未启用记录）、当前和
刷新历史 token、临时密码证明 token；字符串与 JSON 键名中的直接引用都会拒绝。
扫描时释放会话锁，完成后重查身份和已知凭据集合；状态竞争返回重试，旧账号不能继续
操作新账号配置。模型代理原有凭据守卫继续生效，自建服务商归档仍不激活模型。

此守卫保护 Native 当前进程已知的值，不承诺识别未知历史、其他账号或编码后的任意秘密，
也不构成后端 CAS。刷新轮换后 vault 保存失败的完整恢复、原始 K-brain token 入口、
多写入方协调、WebUI/Android 密钥路径和真实平台验收继续保持未完成。

本轮 fresh 定向结果为账号/API 25、WebSocket 6、后端模块 11、设置 127 项通过，另有
2 项按原规则忽略。三个备份用例曾在 READY 等待阶段超时，单项运行均通过；仅对备份
夹具的进程启动加串行锁后，设置模块 127 项整体通过，未修改生产期限或业务断言。
这项夹具调整不证明 Windows 冷启动根因已解决。源码摘要及不可变日志见同步报告。

### 刷新轮换后的验证与持久化重试

服务器刷新成功可能已经消费旧 refresh token，因此新令牌在再次请求 current-user 之前
就进入 Native 私有的待提交状态。只有身份与原账号一致且系统凭据库写入成功，调用方
才取得可用令牌和更新的摘要。临时身份服务失败或 vault 保存失败保留新候选；后续请求
先完成该候选的验证和保存，不会重用已经消费的前一枚 refresh token。候选自身过期时，
从其最新 refresh token 继续轮换。并发消费者共用原有刷新锁，普通请求不能绕过待提交状态。

启动恢复同样保留轮换候选和预期账号，失败重试不重新加载旧 vault 值，也不降级到离线
profile。新的 OAuth 授权使旧恢复代次失效，并尝试清理候选；迟到恢复不能覆盖新登录。
退出与会话失效在清除边界内捕获最新已提交及待提交凭据，在释放状态锁后尝试撤销二者。
清除失败仍保留原可重试句柄及候选，维持既有的退出失败契约。

候选不进入渲染层、日志、备份或明文磁盘文件；这是当前进程内的故障恢复，不是服务器
轮换与 OS 凭据库之间的分布式事务。进程在持久化成功前被终止，下一次启动可能需要
重新授权，不能把内存候选称为跨崩溃持久恢复。实际系统 vault 故障和原生 UI 仍需验收。

本阶段 Native 定向共 84 项通过、1 项按原规则忽略，其中账户/API 33 项包含八组新增
回归；一次性令牌夹具会拒绝消费过的 refresh token，覆盖 OAuth/旧密码会话、身份与
保存失败、并发重试、候选过期、退出/清除失败/切号及迟到恢复。前端会话 12 项通过，
验证保存失败后保留句柄重试、启动错误不降级到旧明文导入。故障由隔离存储夹具注入，
没有声称这些结果等同于真实系统 vault 被锁定或跨平台 UI 验收。

### 执行后端的公开传输入口

Desktop 连接与 profile 激活 IPC 现在返回 `PublicBackendConnection`，其中是 Native 独立
监听端口和随机 `za-backend-` 能力。真实 `KBrainBackendConnection` 不再实现序列化，
仅用于受信 Native 适配器与私有备份路径。公开连接保持原 JSON 字段及稳定 storage ID，
不再把真实 K-brain bearer token 交给渲染层。后端重启关闭旧入口并更换公开能力。
Native 可移植配置守卫保留当前进程已知的真实令牌与公开能力历史，关闭或重启后仍拒绝
其字符串和 JSON 键名别名，避免把可用运行时授权写入导出或归档。普通自建归档继续允许。

代理只连接已验证的数字 loopback 后端，不使用系统代理或跟随重定向，不向后端转发
调用方 Cookie、Origin、代理认证或传输级请求头。通用 Provider secrets 及网络代理配置

## 桌面终端读取与隧道桥

LiveAgent v2.0.15 的宿主桥只注册到已验证账户的本机 K-brain 进程。每个进程使用独立的回环监听地址和随机凭据。账户租约失效、进程退出、切号或重启后，旧凭据不能再调用。桥只接收本机交互 Agent 的工具请求，不授予设备 WebUI、云端、计划模式、沙箱或无人值守运行。终端读取不发送输入，隧道按当前工作区过滤，创建和关闭沿用 Remote 开关及原有审批。已由授权操作提交的隧道仍由原有 Remote 状态和账户存储管理。
