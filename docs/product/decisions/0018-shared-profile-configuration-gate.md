# 0018：profile 内共享的配置写入边界

- 状态：部分实施；共享互斥边界及桌面快照/批量协议已接线，Native viewer HTTP 版本约束见 ADR 0020；设备 Native 提交入口见 ADR 0022；真实设备、Gateway 与恢复验收仍待完成
- 关联：ADR 0010、0016、0017

备份恢复使用多域补偿。若恢复、补偿与普通 HTTP/原生偏好写入分别持锁，后一次补偿会
覆盖另一个写入方已经保存的设置。仅将恢复函数或某一种设置 API 串行化不能解决此问题。

协调器以 Native 根据实际数据根派生的稳定 storage ID 为键，供同一 profile 的配置
HTTP、原生偏好读取/批量保存、备份采集/恢复/补偿、WebDAV 和已有设备 SSH 写入共用。
持有中的操作保留协调器自身；即使后端管理器被替换，也不能在旧操作结束前创建另一把
独立锁。不同 profile 独立，协调器身份不是授权凭据。

HTTP 配置请求在响应结束前持有边界。已收到的写请求由服务端拥有的任务执行，客户端
断开不会直接释放锁，让后续恢复或补偿越过尚在应用的写入。profile 失效仍取消请求，
普通模型流、工具执行、模型发现、历史与文件传输不持有这把配置锁。

规范备份采集在边界内读取真实后端，并在同一 SQLite 读取事务中采集原生字段。恢复从
采集私有回滚副本起，到应用、补偿与完成记录结束，都持有同一边界。WebDAV 下载后
记录同步摘要也在此边界内，避免把另一笔尚未上传的新编辑误记为已同步。上传的外部
网络传输不长期占用配置锁；已采集的快照及原有目的地/摘要校验继续使用。

工作副本验证通过线程局部守卫禁止发布自动同步脏信号；它不抑制别的 profile 的真实
提交。原生偏好批量保存持锁至系统代理和设备连接的提交后刷新结束，之后才发布新快照。
STT 广播重新读取当前快照，不使用较旧的提交正文覆盖后来状态。

桌面快照与复合保存现由 ADR 0019 的规范批量 IPC 实现。Native viewer HTTP 已通过 ADR 0020 约束调用方读取版本，Gateway 转发仍需端到端验证，
设备一般设置现经 ADR 0022 的 Native 规范入口提交后确认。
同路径 debug 多实例、未知提交结果、后端内部异步写入及完整恢复/重启验收也需要继续
核对；不得把请求串行化、少量并发测试或原生偏好 CAS 当作统一配置事务协议完成。

该改变保留配置/备份格式、现有 profile 和私有回滚文件，不激活旧自建服务商或修改
托管模型选择。验证结果及当前限制记录在 v2.0.0-beta.20 同步报告。
