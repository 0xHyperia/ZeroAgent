# ADR 0011：Windows 后端冷启动等待上限

- 状态：已采纳，验收中
- 范围：Windows Desktop；关联 ADR 0007、0008

## 证据与决策

锁定 K-brain 原生配置备份回归出现启动超时。默认并发完整库曾 1142 通过、4 忽略；
后续与构建并行时出现多个启动/时限失败。降低并发和单独逐项运行仍能复现启动超时，
不能把所有失败都归因于测试并发，也不能以修改业务断言或重复运行掩盖。

在独立 CLI、空白测试数据根、未提交生成请求的诊断中，分别观察到 30.876 秒和 53.087 秒
后才打印 READY，随后 `/v1/health` 返回 200 和 `kbrain.agent.v1`。53 秒样本显式使用原生端
同样的 `LIVEAGENT_KBRAIN_PROXY=direct`。另一未显式指定代理的样本在 60 秒诊断期限内
没有 stdout/stderr。源码核对表明监听和 READY 位于存储及运行时初始化之后；尚未定位
具体耗时阶段。60 秒是有限的等待预算，不保证所有环境都能在该时限启动。

Windows 的生产启动等待上限从 15 秒改为 60 秒，其他桌面平台保持 15 秒。真实后端夹具使用
同一平台预算；Node 夹具由共享 helper 保留其他平台既有期限，只给整体测试预算补入相应的
启动差额，不修改模型、ACK 或命令等待期限。该调整允许已经观察到的冷启动完成，不增加
重试循环，不改变健康/协议校验、
profile 绑定或密钥边界。仍以取消状态和父进程生命周期结束等待并清理所属进程树。

## 验收与限制

保留模拟后端的短期限超时、输出关闭、协议不符、启动取消与子进程清理测试，不延长这些
用例来回避错误。重新运行真实后端备份、模型代理和完整原生库。其余 MCP、Git、终端及前端
时限失败须分别验证；不能用本决策将它们视为已解决。需继续定位 Windows 启动耗时及验证
真实桌面启动体验。诊断回执为工作区 `.codex-artifacts/startup-probe-results.json`。

Node 真实后端夹具同时显式指定 `-data-dir`，固定子进程的 HOME/USERPROFILE/LIVEAGENT_HOME，
清除旧 K_BRAIN_HOME，并显式使用 direct 访问本地模拟服务。旧轨迹夹具只指定了配置与会话
目录，可能触及用户默认 `.liveagent`；其原有通过结果不能证明隔离。保留既有默认目录，
不据此声明其历史内容未变；新夹具需在隔离目录重新验收。生产原生启动本就明确传入
`-data-dir` 且不传 `-legacy-desktop-dir`，未采用该夹具的默认目录路径。

切号请求在等待 active-profile 锁之前发布独立代次，取消仍持锁的旧后端启动；启动路径在取得
start 锁前后核对捕获的取消代次，过期请求不能重新使用新代次启动旧目录。同账号重连不改变
请求代次；不同账号首次激活后仍重启原生进程。验收包括持锁请求、A/B/A 的旧请求拒绝、
创建子进程/数据目录前取消及退出后拒绝新激活。Windows 实际启动期间的账号切换和 UI 行为
仍须单独验收，不能用这些状态回归代替。

原生 profile 改用服务端身份验证后，前端 IPC 外层期限同步由 20 秒改为 90 秒，以覆盖
10 秒身份请求和 Windows 60 秒后端启动预算。此前 20 秒会在 Native 正常等待时提前报错。
这只修正启动层的预算关系；Native 60/15 秒、浏览器健康检查 5 秒，以及模型/SSE、ACK、
命令和取消期限均未改变。受控时钟回归验证 55 秒启动可以完成且 90 秒仍会终止等待，
实际 Windows 冷启动根因和真实 UI 验收仍待完成。
