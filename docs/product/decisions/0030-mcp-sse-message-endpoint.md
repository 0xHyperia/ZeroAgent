旧客户端的 SSE `messageUrl` 支持绝对地址及相对于 GET 地址的相对地址。
显式值优先于服务器的 endpoint 事件；服务器不发送 endpoint 时仍能初始化。
保留该结果，在 Go 模式继续传递 sse 协议和 messageUrl，HTTP/stdio 的历史冗余值
保留但不作为 SSE 覆盖使用。普通 SSE 自动发现沿用 SDK；旧自动推测端点的兼容仍待补齐。

显式覆盖在现有 SDK 的 HTTP 传输适配层完成：GET 响应先提供配置端点，再过滤其后
endpoint 事件。SDK 继续拥有 JSON-RPC、协议协商、工具调用、取消和会话；不增加 Agent 循环。
首个合成事件单独返回，避免 SDK 初始化的临时缓冲读取器预读并丢失后续消息。
适配器跟随原 GET 的拥有期和关闭；相对地址解析不把原始私有 URL 写入错误。

Native OAuth 的 SSE 目标摘要纳入解析后的 messageUrl。无覆盖的旧摘要字节保持，
新增、移除或修改端点要求重新绑定，不自动迁移旧授权。Bearer 仅用于同源端点，
仍使用现有逐请求解析、401 刷新、凭据历史过滤和资料租约。显式静态配置保留原有
跨源地址能力。Go 草稿诊断和 Native 私有字段合并也把 messageUrl 纳入身份，
改变端点不能继承旧请求头或凭据引用；旧记录继续保留供回退。
