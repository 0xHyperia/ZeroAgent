# 0015：旧自建服务商只归档，不启用

- 状态：已采纳，主要路径已实现并通过定向验证；端到端范围见同步报告
- 来源：用户明确选择“保留配置用于导出和回退，仍只使用托管模型”
- 范围：旧版 ZeroAgent 配置迁移，以及这些归档记录的备份和恢复

客户端模型选择继续只显示 USA-Zero 托管 Provider。旧版自建服务商属于需要保留的数据，
不能因为当前界面的 Provider 过滤而丢弃，也不能通过迁移把它们加入可执行模型列表。

旧配置的自建服务商由 Native 读取、校验并存入当前 profile 的独立 SQLite 归档表；不写入
K-brain Provider 注册表，不把其密钥返回给配置读取或预览前端。归档与新定时任务/钩子
在同一 Native 事务中按 ID 补缺，已有记录不覆盖。源库只读，确认指纹覆盖归档内容。

已选 profile 中若还留有旧 SQLite Provider 缓存，设置读取仅在 Native 内按 ID 补充归档，
原缓存保留用于回退，托管记录及凭据别名拒绝进入归档。设置读取响应不返回这些凭据。
启动不再从 SQLite 或浏览器旧副本自动注册自建 Provider，也不以旧默认模型覆盖规范模型。
缓存归档的完成标记与内容在同一事务保存；失败可以重试。明确恢复归档（含空数组）也保存
该标记，防止下次读取又从旧缓存复活已清空的归档。恢复前先完成当前缓存保全，再采集
回滚副本和合并旧备份。

归档纳入配置备份的独立 `archivedProviders` 域。导出只在 Native 采集自定义凭据；恢复
仍写入归档表，不转换为可执行 Provider、不修改默认模型。该域缺失时保留当前归档，
显式空数组表示清空归档，恢复前的私有备份用于回退。托管 Provider 与已知托管密钥别名
不允许进入归档。迁移日志只包含指纹和条目数量。

引用旧自建服务商的任务保持关闭。归档不提供模型执行能力；用户需要在启用任务前重新
选择当前账户的托管模型。迁移 UI 明确说明“归档、不启用”，不声称可使用自建模型。

0.3.23 实际导出的 schema 1 备份，以及已支持的旧 schema 2，在本地和 WebDAV 恢复时将
`providers` 转入独立归档，预览显示为归档，按 ID 补缺且保留已有编辑；旧默认模型不应用。
原文件和版本号保留，新导出使用独立归档域。旧托管行排除后，其凭据别名仍须校验其他
配置域。现有 schema 3 Provider 域的兼容逻辑单独保留，不把新归档域升格为可执行域。
完整恢复的多写入者
并发及回滚验收继续由 ADR 0010 跟踪，单个 Native 事务通过不等于整体恢复原子。

验证覆盖：原库不变、归档独立于 K-brain、前端不收到归档凭据、重复导入保留已有归档、
账户 A/B 与重启、归档/任务事务一起回退、备份往返仍不激活 Provider、旧备份无此域时
保留当前归档，以及受保护凭据拒绝。
