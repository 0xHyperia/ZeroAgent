# 0020：Native viewer HTTP 的配置版本与批量保存

- 状态：Native viewer HTTP 已接线；设备通用设置持久化后 ACK、真实 Gateway 转发验收、恢复界面和跨平台矩阵仍待完成
- 分类：adapt 上游配置 REST 与客户端；统一配置能力整体仍为 partial
- 关联：ADR 0016、0018、0019

Native viewer 的配置请求由所属 profile 的规范配置服务处理，复用桌面 IPC 的读取、版本校验、私有恢复副本、MCP 私有字段保留与失败补偿。服务捕获实际后端连接、后端根和设置根，通过弱引用取得当前 Native 授权状态；每次请求都检查当前连接及 profile，不能因为视图还持有旧地址而访问另一个空间。模型、工具、文件和 SSE 继续使用流式代理，不参与配置互斥。

完整配置读取返回强 ETag，绑定实际读取的 Go 文档、Native SQL 偏好版本、私有 MCP 摘要、协调器命名空间/计数与资源种类。写入须提供对应读取的 If-Match；缺少版本返回 428，过期、跨资源或不匹配版本返回 412。HEAD 与 If-None-Match 保留条件读取语义。Markdown 模板列表不是全局模板编辑文档，因此不为它签发可借用的编辑版本。ETag 是并发控制信息，不能替代 profile bearer 授权。

服务通过 X-ZeroAgent-Configuration: zeroagent.configuration.v1 声明扩展。支持该扩展的浏览器使用 GET /v1/configuration 读取一次后端快照，以 PUT /v1/configuration 提交一次服务商、MCP、全局模板和项目提示词编辑；该入口不接受 Native 偏好、设备连接或其他未授权字段。原有单资源入口也要求版本，并复用相同规范写入。MCP 元数据编辑保留隐藏值和工作区/工具策略，普通 reload 通过同一规范路径重建。外部私有文件与运行态不一致时，沿用 ADR 0019 的重启核对要求；未知结果恢复界面未完成。

SDK 把响应版本放在当前返回文档的只读、不可枚举元数据中；写入显式接收基线版本，不能自动读取最新版本为旧编辑补票。浏览器复合编辑仅能在完整后端基线等于本窗口上次成功提交意图时继承其版本，失败或重新读取会清除继承关系。输入模态补齐也使用实际快照版本，随后重新读取确认。没有扩展声明的独立 Go 后端继续走既有 REST 协议，不假装支持 Native 批量入口。

模板创建/启用操作遵循锁定 Go PromptStore 的单启用约束；PATCH 的 null 字段不覆盖原值，null baseRevision 表示未提供额外的提示词版本条件。界面偏好仍可在配置拒绝时独立保存。设备一般设置仍存在依赖 WebView 持久化的路径，本决策没有将它视为已完成；设备 RPC 与 Gateway HTTP 转发需要分别验证实际版本及 ACK 顺序。

生产后端启动必须携带该规范服务，Native 状态使用 Arc 接收器并向服务传递弱引用，避免状态与代理之间形成保留环。仅测试构造器可以建立不带配置存储的传输夹具，用于流式/取消/请求头测试；它不能作为生产配置策略的验证证据。真实 Go HTTP 配置回归另经生产适配入口运行，账号、设备与实际桌面 UI 验收继续另列。
