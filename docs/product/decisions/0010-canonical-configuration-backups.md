# ADR 0010：v2 规范配置备份与迁移记录

- 状态：已采纳，实施与验收中
- 范围：Desktop 配置导入、导出、WebDAV；关联 ADR 0004、0007、0008

## 决策

v2 的 Provider、MCP 与全局提示词从当前 profile 的 K-brain 接口采集和恢复。SQLite 继续
提供可移植原生偏好、模型故障转移与 STT；不能把旧 SQLite 副本当作完整的 v2 配置。
备份 schema 3 增加自建 Provider 的默认模型，并继续读取 schema 1/2。账户托管 Provider
与其默认模型不作为可移植配置；目标账户重新取得自己的托管服务商。
按用户后续选择与 ADR 0015，旧 schema 1/2 的自建服务商恢复到独立归档，不注册模型；
已有归档按 ID 保留，预览显示归档数量。schema 3 的现有 Provider 域兼容逻辑单独保留。

原生端从已激活状态取得当前后端，只接受数字 loopback，禁止代理和重定向；前端不能
提交后端地址或 token。后端不可用时导出失败，不以空配置代替。自建密钥只在原生备份
路径解析。托管行整条排除，原生代理还检查已知托管密钥被改名或放入其他配置字段的情况。
检查保留当前进程内已知密钥及本机模型能力凭证的摘要历史，保护对象可跨代理关闭持有；
能力凭证属于当前 profile 的运行时授权，也不能改名为自建密钥后导出。不持久化原始托管密钥。
Desktop 账号凭据已按 ADR 0016 移到 Native；其当前进程已知值的守卫也接入这些配置入口。
WebUI/Android 密钥路径、完整写入边界和真实账户绕过验收仍未完成，不能泛化桌面结果。

恢复先验证输入并保存当前规范配置的私有回滚副本，再依次应用后端配置与原生配置。跨设备
Provider 先匹配本机身份，再同步改写默认模型和故障转移引用；已有托管 Provider 不被覆盖。
失败尝试恢复原配置；自动恢复失败时保留并明确显示回滚路径。成功或失败后界面均重新读取
后端，不能继续用恢复前的内存值编辑。独立写入方与多域恢复之间尚无统一后端事务，必须
保留并发写入验收，不能称为原子恢复。

锁定 K-brain 源码的 `internal/backend/settings.go` 中，设置 PUT 仅在单次请求内持有配置锁，
更新结构不接受 expected revision；GET 也不提供可用于条件写入的 ETag。仅在 Native 中加锁
不能覆盖前端或 Gateway 的独立写入，先读后比较同样不能替代后端 CAS。后续实现需要统一
这些写入的受信入口，或提供可验证的后端条件事务；在此之前，失败补偿仍可能覆盖并发编辑。

导出和回滚文件通过私有临时文件完整写入后提交。恢复预览的指纹绑定当前 profile 与文件
内容；本地文件、远端内容或目标空间在确认后变化时拒绝应用。远端 config 仍须通过独立
manifest 的大小与 SHA-256 校验。

WebDAV 新快照写入 `v2/` 布局，避免旧客户端覆盖 schema 3。手动读取在新布局没有 manifest
时回退到旧 `v1/`，读取同一布局的配置并保留预览校验；不自动下载。自动上传维持原生变更
防抖，并在用户启用后每 5 秒检查规范配置，覆盖 WebView 暂停及 Gateway 直接写入的情况。
已上传内容摘要保存在当前 profile，排除易变的 manifest 字段；未变化时不重复上传，目标或
凭据改变时重新确认上传状态。该摘要和 WebDAV 凭据不进入可移植快照。

迁移记录保存在当前 profile 的设置目录，只包含来源格式/指纹、目标 profile、时间、阶段、
结果、条目数和回滚路径。不得记录配置正文、密钥、认证头或后端原始错误响应。开始记录失败
时不执行写入；完成记录失败必须显式反馈，不能把已应用的配置伪装成未改变。

## 验收

使用锁定后端验证规范数据采集、旧 SQL 副本不冒充规范数据、Provider ID 与默认模型映射、
自建密钥恢复/清空、托管密钥排除和别名拒绝、MCP 与提示词、半途失败后的补偿恢复、原始数据
保留、profile 隔离、重启、schema 1/2 读取、WebDAV 双布局和预览后变更拒绝。迁移记录验证
成功/失败/中断阶段与密钥不落日志。实际完成范围以同步报告为准。
