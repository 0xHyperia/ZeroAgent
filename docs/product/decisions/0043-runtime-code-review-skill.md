# ADR 0043：代码审查技能进入当前后端执行链

- 日期：2026-10-27（Asia/Hong_Kong）
- 状态：用户授权修复、补运行时测试、构建运行；不推送

beta.23 保留的 Native 内置技能种子写入原生辅助设置目录，但 Skills Hub 和模型执行均读取
当前账号 Go 后端的 `engine/skills`。因此有源码和静态注册并不代表运行时可用。

在每个后端 profile 启动、打开 Go 进程之前，复用既有所有权标记与备份更新逻辑，只将应用的
`zeroagent-code-review` 种入该后端的 skills 目录。Go 自己管理另外两个内置技能，不复制或
接管它们；不扫描或搬迁用户的旧技能。同名无应用标记的用户技能原样保留，不冒充受信内置；
链接、reparse point、异常类型和超大入口拒绝采用。保持全局开关、工作区选择与账户隔离。

固定 Go manager 只有两个硬编码内置名称，也没有宿主注册扩展。因此增加范围限定的第六
补丁：仅当名称及非链接所有权标记精确匹配时识别应用代码审查技能，复用原 builtIn 字段及
管理保护；最终替换/删除仍在原写锁下复查。前五补丁字节、Go module 和协议不变。
上游提供等价宿主内置注册并通过同组测试后，使用该扩展替代补丁。

技能正文同时适配当前 `subagent` 工具。四个角色以四个独立调用并发执行，background=false、
worktree=false；每个验证者也创建新上下文。不给旧 Agent 的 mode/resume/concurrency 字段
造兼容接口，不增加第二套执行器。每个审查/验证提示都明确只读所给快照、不调用工具、不
修改文件或写远端。此处是模型指令边界，不能描述为后端增加了硬性 readonly 权限模式。

测试须启动真正的 Native profile manager、公开配置 facade、前端 Skills adapter / Hub
视图及 Go Agent。通过本地合成模型检查列表/内置标志、工作区启用、入口正文读取、四路真实
subagent 返回、重启保存和第二账号未被选中，并验证同名用户数据与修改保护。不能仅以文件
存在、静态注册或 HTTP 200 声称完成。测试不访问真实模型服务或操作桌面 UI。

改动不重置配置、凭据或历史，也不为撤销源码主动删除技能文件；既有旧版回退范围不扩展。


四路真实审查还复现了 Windows 上共享轨迹片段的检查/发布竞争：多个审查者同时发现内容
摘要文件不存在，随后重复 rename，碰到已被读取的目标而失败。第七补丁仅在同一个 runtime
session 内串行该不可变片段的存在检查和发布，不把子代理或模型执行串行化，不改格式或协议。
并发写入/读取回归先复现 Access is denied，再验证内容和摘要一致；上游等价修复后撤销。
