# ADR 0013：隧道配置重复上报的处理界限

- 状态：已采纳，实施与验收中
- 范围：Gateway 设备隧道；关联 ADR 0002、0003、0007

控制繁忙回归确认，相同 desired state 每次都会广播快照并启动独立 relay probe。在快速重复
上报下，这会放大控制流量和 goroutine 数量，并使数据请求超过等待期限。

Gateway 逐条比较规范化后的配置，仅在实际变化或连接代次变化时广播。连接使用注册表已有
的 session epoch 识别，避免依赖时间戳精度。新连接获得包含既有 slug 的首次快照；过期、
删除和归属检查仍按当前记录执行。重复探针沿用现有探针期限作为最小重建间隔；relay 只检测
Gateway 与 Agent 的路径，目标名称或地址编辑不需要在该间隔内重复检测相同连接。

新增状态只存在于内存，断开和永久删除时清除。没有配置文件或协议格式迁移，重启或回退
会重建该状态。验证须覆盖大量重复上报时的发送队列、控制繁忙时的数据请求、同一时间戳下
的新连接首次广播、slug 保留，以及既有跨 Agent、过期和流撤销行为。

实际完成范围以同步报告为准；这项修复不替代传输全量、race 和真实设备验收。
