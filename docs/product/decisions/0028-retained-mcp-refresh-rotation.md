# 0028：MCP 刷新轮换的保存失败恢复

- 状态：Native 私有宿主恢复、真实 keyring 与 Go 候选回归通过；其余入口和完整生命周期验收待完成
- 范围：v2 Native → Go 凭据宿主；旧 Native MCP 执行入口仍须收敛

AS 的刷新令牌可能只允许消费一次。新令牌签发后，如果本地保存失败，下一次请求必须
先重试保存这次轮换，不能丢掉新刷新令牌后再次提交旧刷新令牌。未确认保存成功的结果
只留在 Native 内存中，不返回 Go，也不进入 renderer、普通配置、备份或日志。

存储层在条目锁内推进版本，并返回失败阶段和精确重试凭证。凭证拥有 TokenStore，
固定 profile、服务器、存储模式、失败写入版本和待保存记录摘要；它不从稍后的无关
snapshot 推断权限。CAS 拒绝不签发凭证。keyring 已成功、旧文件清理失败，与可能写入
但未获得确认、尚未写入等情况分开记录；报错不等于持久层仍是旧记录。重试只允许原
记录和原版本，成功或其他写入后旧凭证失效，不序列化或格式化凭证内容。

每个私有宿主拥有一个恢复表，最多 16 项，按序列化记录及请求前预留计入 16 MiB 预算。
请求 AS 前预留当前记录大小加两倍 AS 响应上限和固定字段余量，容量不足先拒绝刷新，
不驱逐先前未保存的轮换。AS 完整响应沿用 1 MiB 限制。保存失败后仅保留所需的记录
与版本凭证，释放多余预留。此预算描述所计入的记录字节，不是整个进程的 RSS 上限。

恢复沿用每条目刷新互斥；网络等待不占 profile 或恢复表锁。每次供给先处理待保存结果，
即使一次部分成功的 keyring 写入已让新记录可读，也要完成原保存及清理。重复存储错误
更新失败版本凭证，不再访问 AS；保存确认后才能返回 Bearer。

清除和新保存推进条目版本。新交互授权在开始时也推进版本，阻止旧轮换在新浏览器流程
期间复活。目标摘要、MCP 修改代次、profile 权限及宿主活动状态均参与复查。宿主停止
或 stdout 进程守卫撤销时清空恢复表，仍在 AS 等待的请求返回后会拒绝保存。进程退出
后不恢复这些内存秘密；持久存储仍故障时可能需要重新授权。

验证覆盖真实本机 AS 一次签发后的文件故障、反复失败与修复、普通 store 句柄全部释放、
并发等待者、容量拒绝、新授权/清除/替换、目标与操作代次变更及宿主撤销。keyring 部分
写入和清理失败使用确定性的 vault API 边界夹具，文件、版本及重试走生产实现；这不是
真实 OS keyring 故障注入。既有真实 Windows keyring 合成条目回归单独执行和记录。

最终持久化与账户注销的完整线性化、跨进程存储协调及所有旧 Native MCP RPC 的执行
归属尚未完成。这里的私有宿主回归不能证明所有旧入口已遵循相同的目标和权限边界。
