# ADR 0048：CloudChat 持久任务与独立云端能力

- 日期：2026-10-29。
- 状态：用户目标授权本地实施；不推送、发布、合并上游或部署生产。
- 范围：托管 Gateway、WebUI、Android；桌面设备执行契约保持。

CloudChat 以用户完成写作、资料理解、联网研究、数据分析、成果交付、项目接续和编程辅助的完整流程为目标。阶段与实现可以依据证据调整，不能用计划、演示或 Mock 代替生产候选验收。

托管 Gateway 接受账户范围内的持久 Run，PostgreSQL 保存任务、操作及事件事实，Redis 保留登录会话并承担通知与限流。用户消息与任务接受原子提交；请求标识去重并校验内容指纹。Worker 使用租约和执行代次提交输出，终态与规范历史一致保存。断开页面只解除订阅，显式取消及账户失效停止执行；模型调用中断后保存已提交内容并准确标记中断，不自动重发可能已计费的请求。恢复输出不代表恢复外部操作。

云端文件、工具、对象存储和 E2B 使用独立能力、资源归属与预算，分批建立真实接线。设备协议、本地工具和租约不向 CloudChat 复用。Go 持有服务端编排，前端消费协议；SDK 适配层不新增 Agent 循环。服务端解析平台 key ID，真实凭据不保存到 Run、公开事件或沙箱。

当前 v2 会话和消息继续使用原规范存储，只增加应用拥有的任务与事件表，不重写或清理用户数据。已有支持的 completions 入口将适配到同一任务服务，不维护第二执行链。托管任务仅在托管服务中启动，不启动桌面侧车内的云端执行服务。

Android 在 Native 内持有凭据并进行有界字节流传输；订阅、取消和迟到输出绑定原账户代次。浏览器取消订阅与服务端取消 Run 是两个操作。

验证包含请求去重/冲突、账户隔离、接收与历史原子性、事件重放、取消竞态、Worker 失联与未知结果、凭据反射、流式传输及原设备回归。外部服务、真实账号、收费额度与真机尚未验收的内容逐项保留，不以本地夹具推定完成。源码撤销不承诺旧版本读取新增任务；故障时保留现有数据与结果。

2026-10-29 根据完整 Web 工作流程继续完善：当时采用原子前缀分支。编辑重发的现行规则见 [ADR 0074](0074-in-place-edit-resend.md)；显式 memory 默认关闭，不自动提取个人信息。项目指令、关联资料及主动启用的 memory 在新模型调用时读取，并记录不含原文的版本来源。新增文件、解析、工具账本、Workspace/cleanup 和成果表为 CloudChat 自有数据，不迁移旧供应商配置或恢复已撤回的品牌修改。

E2B SDK 由独立内部适配器承接，管理凭据只在该服务；Go 仍持有唯一工具循环。VM 观察回执与执行授权分离，迟到/冲突分配仍保留清理事实。正式原件/成果通过校验后进入对象存储，不能依赖 VM 活跃或暂停来保证可下载。当前秒预留与模块边界是实现基线，后续以真实费用/容量和用户流程校准，不冻结表、接口或实施阶段。

生产边界审查复现：同一模型读过项目、记忆或附件后，任意模型生成的搜索词/URL可能携带私有内容；SSRF校验、凭据过滤和“不可信来源”提示词不能建立资料出站授权。因此在唯一Go循环内增加公开研究阶段。用户明确确认的公开主题冻结到Run及请求摘要；研究上下文只能包含该主题与当前阶段公共来源，不能读取私有历史/项目/记忆/附件或执行工作区工具。阶段结束后不可重新开启，撤销其内部能力并进入私有综合；综合可以查阅本Run已有来源，但不能再次发出搜索或网页请求。总时间、轮数和工具预算统一，至少保留一轮综合，不新增第二Agent循环。Web复用联网入口并默认关闭，每个新Run须明确确认其公开主题，不能将模型建议或旧偏好视为授权。与逐工具弹窗相比，该方案保留公开主题内自动改写和多跳研究；需要新主题时由用户再次明确选择。

同次审查还要求：未知远端执行/清理状态不能被取消请求覆盖为“已确认停止”；owned allocation即使网络或envd漂移仍能通过明确cleanup-only观察找到并终止，观察本身不授权恢复执行。新增恢复partial消息按会话现有最大时间递增，避免恢复目标墙钟回退打乱规范历史。这些调整依据真实负例及隔离回归，不改变核心基础设施方向或旧用户数据。
