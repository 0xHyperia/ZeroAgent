# 0032：旧 SSE 消息端点的推测与迟到事件

- 状态：Windows/WSL MCP 全包与独立 Native/Go 候选通过，macOS 编译验收中
- 范围：未配置 messageUrl 的旧 SSE；显式覆盖继续由 ADR 0030 决定

旧 Native 最多等三秒 endpoint 事件；仍未取得端点时，仅将 URL 路径的末尾
`/sse` 替换为 `/message`，保留前缀和 query。其他路径明确要求提供 Message URL。
以后收到有效 endpoint 时更新后续 POST 的地址。该兼容行为在切换到 SDK 后需补齐。

继续使用 SDK SSE 会话和 JSON-RPC。HTTP 适配层只处理端点发现：保留原 GET
拥有期、三秒预算、取消和清理；先向 SDK 单独提供一个规范 endpoint 帧，避免
其临时事件读取器预读丢失后续消息。endpoint 事件不作为 JSON-RPC 消息传入。
未显式覆盖时，迟到端点更新后续 POST；请求在凭据传输层之前改写，沿用其接收方
和重定向保护，不能绕过 Native 的同源约束。草稿/凭据目标摘要不增加推测值。

端点前的消息保留到 SDK 接管；该队列累计上限为 4 MiB，超限报错并清理 GET。
空或无法解析的 endpoint 忽略；可解析但不支持的 scheme 明确拒绝，避免发到旧地址。
这是端点发现期间的队列上限，不改变正常工具输出或调用预算。

验证须覆盖公告端点优先、缺失后的推测、前缀/query/编码路径、迟到更新、首帧预读、
取消部分事件、无可推测路径、凭据接收方和重复启停。协议版本回退另行验收；
不能以此宣称旧 Native 的所有协议行为已替代。第七版来源在其跨平台验收期间保持冻结，
新实现只修改独立的后续源码副本。
