## 结论

建议跟进 v2 架构：让 K-brain 成为设备 Agent 的模型、执行与持久化后端，将 ZeroAgent
差异集中在账户、设备路由、托管 Provider、平台能力和发布适配层。继续维护旧前端 Agent
循环会与上游的执行状态、审批、队列和历史模型持续分叉。

这是一项跨版本迁移。应从当前 ZeroAgent 产品基线建立隔离集成分支，面向精确 Release
保留真实 Git 合并关系，分阶段审查和验收。无需逐版合并所有中间版本，也不应靠逐个
cherry-pick 代替最终的上游祖先关系。

本轮建议优先迁移 Desktop 与设备 WebUI。Cloud Chat 继续通过现有账户化云端接口运行，
Android 继续使用嵌入 WebUI；二者的后端迁移另行验收。不能把上游单实例 K-brain 远程
目标直接视为 ZeroAgent 多账户 Cloud Chat 的替代实现。

## 架构变化及对 ZeroAgent 的影响

### 1. 执行状态移到独立后端

上游删除了 `agentRunner.ts`、多项前端 Provider payload/stream 实现，把模型适配、Agent
循环、工具、审批、子代理和历史交给 K-brain；React 主要投影 session/run/event 状态。
原生宿主通过 `kbrain_backend_connection` 管理本机动态回环地址和进程令牌，健康协议为
`kbrain.agent.v1`。

优先采用上游 HTTP/SSE、ACK 丢失查询、事件游标续订和进程清理实现，保留 ZeroAgent 的
远程设备注册与选择租约。客户端展示的 session ID 不能代替账户、设备、工作区的授权依据。

来源：[上游架构](https://github.com/Stack-Cairn/LiveAgent/blob/47a0d1c3e1f6719975678ca42d4c212c2ba278ec/docs/architecture/overview.md)、
[传输恢复边界](https://github.com/Stack-Cairn/LiveAgent/blob/47a0d1c3e1f6719975678ca42d4c212c2ba278ec/docs/design/kbrain-transport-boundary.md)。

### 2. K-brain 是新的交付依赖

Release 锁定 `Stack-Cairn/K-brain@v0.107.6-beta.18`，源码修订为
`1f27ade557fe268c76853f83f4fb7aa32d078eac`，包含四种桌面平台的 backend/computer
二进制与 SHA-256。Tauri 还增加本地 Gateway sidecar，因此桌面包交付涉及三个配套程序。

ZeroAgent 应沿用精确版本与校验和，随整包更新，不在用户首次启动时下载不确定版本。
新增依赖的源码、许可证、内嵌 Computer Use 资产和最终签名包仍需单独审核；本轮没有下载、
执行这些二进制，也没有审计 K-brain 全部源码。

上游锁文件没有 Android 平台条目。Android 构建必须显式排除桌面 sidecar、启动逻辑和桌面
构建前置命令，并保持其 WebUI、OAuth、安全存储与升级流程。

来源：[固定依赖清单](https://github.com/Stack-Cairn/LiveAgent/blob/47a0d1c3e1f6719975678ca42d4c212c2ba278ec/scripts/release/kbrain.lock.json)、
[Tauri 打包配置](https://github.com/Stack-Cairn/LiveAgent/blob/47a0d1c3e1f6719975678ca42d4c212c2ba278ec/crates/agent-gui/src-tauri/tauri.conf.json)。

### 3. 数据目录与会话映射需要改造

上游原生后端默认使用 `~/.liveagent`，优先读取 `LIVEAGENT_HOME`，兼容 `K_BRAIN_HOME`；
文档还描述从旧应用目录及 `~/.k-brain` 导入。前端 `mapping.ts` 将托管连接统一映射到
`liveagent-managed-kbrain`，并未加入 ZeroAgent 账户范围。

建议由 ZeroAgent 宿主统一解析执行上下文：本地离线 profile 与已认证账户 profile 分离，
用不透明、稳定的 scope 选择数据根和后端实例。会话映射、迁移进度、失败记录、队列及图片
任务缓存均绑定该 scope 和稳定存储身份，不依赖随机端口。账户切换需取消旧订阅、停止或
隔离旧实例、清除展示缓存；安装身份保持稳定，不随账户或会话过期改变。

具体目录结构需通过新的 ADR 与迁移夹具确定，不能仅把 `.liveagent` 字符串替换成
`.zeroagent` 就认定完成迁移。默认不扫描或导入其他产品的数据。迁移必须可重入、可中断
恢复并显示失败明细；保留旧历史及备份，验证附件、分页、分支、轨迹、checkpoint 和工作区
绑定。旧数据没有可信账户归属时，应进入隔离的本地迁移候选区，由明确的归属流程处理。

来源：[后端数据根选择](https://github.com/Stack-Cairn/LiveAgent/blob/47a0d1c3e1f6719975678ca42d4c212c2ba278ec/crates/agent-gui/src-tauri/src/services/kbrain_backend.rs)、
[会话映射](https://github.com/Stack-Cairn/LiveAgent/blob/47a0d1c3e1f6719975678ca42d4c212c2ba278ec/crates/agent-gui/src/lib/kbrain/mapping.ts)。

### 4. 托管 Provider 不能采用通用明文读取流程

上游新增 `POST /v1/settings/providers/{id}/secrets`；客户端只提交 `{confirm:true}`。
这不是 USA-Zero 的二次认证证明。ZeroAgent 现有托管密钥复制流程要求验证账户密码。
仅在 UI 隐藏按钮不能保护可直接调用的后端接口。

迁移时必须区分用户自建 Provider 与 USA-Zero 托管 Provider：保留稳定 Provider ID、分组、
模型权限和密钥轮换语义；托管密钥不可通过通用 reveal、导出、编辑或历史导入接口泄露。
优先评估让 K-brain 经受认证的 ZeroAgent 代理执行托管模型请求，避免持有可读取的原始
托管密钥；如果必须存储原始密钥，需要后端级读取策略和二次认证绑定。该代理或后端策略
尚未实现，也未证明现有 K-brain 协议足以零修改支持。

来源：[上游明文读取客户端](https://github.com/Stack-Cairn/LiveAgent/blob/47a0d1c3e1f6719975678ca42d4c212c2ba278ec/crates/agent-gui/src/lib/kbrain/client.ts)、
本地 `crates/agent-gui/src/pages/settings/RelayProvidersSection.tsx`。

### 5. Gateway、Cloud Chat 和图片委派是不同边界

上游 Gateway 使用通用管理 Token / Agent Token，可配置一组 K-brain URL、Token 和目标 ID；
这与 ZeroAgent 的 USA-Zero OAuth、账户会话和执行租约模型不同。ZeroAgent 应保留
`internal/account/**`、认证器接口、设备所有权和路由验证，把上游新协议接到这些边界内。
不能恢复已删除的通用登录页或 Agent 管理 API。

现有 Cloud Chat 通过 `/api/web-chat/completions` 运行。首阶段保留该路径，适配共享 UI，
由服务端继续限制可执行能力，不连接共享的桌面 K-brain。未来若迁移云端执行，需要独立
设计无本地工具的后端和多租户存储、配额及撤销机制。

生图是单独领域：上游已有可信 principal resolver、backend grant 和签名委派接口，并非
所有图片路由都只有单用户设计；但自带的本地 single-user adapter 不能用于生产多账户。
应从 ZeroAgent 已验证的账户会话派生 owner/backend grant，复用签名委派，并测试越权资产
访问和任务恢复。账户适配完成前延后开放托管 WebUI 图片工作台。STT 延续 v1.2.6 的决策，
不恢复全局共享凭据服务。

来源：[Gateway 入口](https://github.com/Stack-Cairn/LiveAgent/blob/47a0d1c3e1f6719975678ca42d4c212c2ba278ec/crates/agent-gateway/internal/server/http.go)、
[K-brain 目标](https://github.com/Stack-Cairn/LiveAgent/blob/47a0d1c3e1f6719975678ca42d4c212c2ba278ec/crates/agent-gateway/internal/protocol/pbws/server.go)、
[图片授权边界](https://github.com/Stack-Cairn/LiveAgent/blob/47a0d1c3e1f6719975678ca42d4c212c2ba278ec/crates/agent-gateway/internal/handler/image.go)。

## 目标结构

```text
ZeroAgent Desktop UI
  ├─ ZeroAgent 账户 / Provider / 执行目标 Adapter
  ├─ Tauri：原生能力、稳定安装身份、按 profile 管理子进程
  └─ 本机 K-brain：设备 Agent 执行、事件、工具、历史
                         ↑
设备 WebUI / Android → ZeroAgent Gateway：OAuth、账户、设备与工作区租约

Cloud Chat WebUI / Android → 现有账户化 Cloud Chat API → USA-Zero
```

托管 K-brain 令牌只用于对应本机 profile 的后端，不能当作 OAuth Token 或设备注册凭据。
不向远程 WebUI 下发可绕开 Gateway 授权的本机后端令牌。能力判定除 UI 显示外，还必须由
Gateway 和实际执行入口验证。

新功能优先级低于既有契约。不能通过临时删除 Cloud Chat、Android、账户切换或密钥保护来
达成“构建通过”。旧 Agent runner 只在新的设备执行路径验收后移除，不长期双写历史或
同时运行两套工具循环。

## 迁移、回滚与维护成本

- 迁移开始前对旧数据做一致性备份，保持来源只读，记录源内容版本、目标 scope、导入结果和
  错误。附件及上传目录不能仅迁移数据库索引。
- 旧版本回滚使用旧数据快照；v2 新产生的消息不能假定可由旧程序读取。验收前需要规范数据
  导出或回迁方案；没有完成回迁时必须明确会损失哪个时间段的新数据，禁止覆盖旧快照。
- Gateway 协议、桌面版本、移动客户端和生产镜像应有兼容窗口或清晰拒绝信息。恢复旧镜像时
  配套恢复相应数据库/配置快照，不能仅回退容器标签。
- 主要收益是删除设备端重复的 Provider 请求构造、Agent 循环与持久化协调。新增维护面是
  K-brain 版本/供应链、profile 隔离、托管 Provider Adapter、各端能力和迁移协议。
- 优先使用现有上游接口。只有证明确需后端级账户或 Secret 策略且无法通过受认证代理实现时，
  才考虑最小 K-brain 补丁；避免现在就维护第二个大范围后端 fork。
