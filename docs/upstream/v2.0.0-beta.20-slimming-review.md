# v2.0.0-beta.20 差异审查与精简方案

日期：2026-10-25（Asia/Hong_Kong）。状态：**方案审查，尚未实施删改**。

首要目标是以上游维护公共能力，降低后续同步所需的人工改造，同时保留 usa0 定制。建议保留 USA-Zero 产品边界，采用上游执行核心，先撤掉无实际消费者的自定义接线，再缩薄仍有用途的适配。已有实现或 ADR 不自动成为必须保留的产品要求。

本轮遵照用户要求停止扩展兼容范围，只读取代码、比较固定版本并记录方案；未新增兼容代码，未删除功能，未完成合并或发布。原实施任务保持暂停。

## 维护准则（2026-10-25 用户明确）

实现选择顺序为：**上游原生能力 → 上游配置/扩展入口 → 独立的 usa0 模块与窄适配 → 必要的最小补丁**。不能因旧本地实现已存在，就继续维护另一套公共引擎或扩展私有协议。

- **上游维护区：** Agent、模型协议、工具与审批、session/event、通用资源管理及公共 UI，尽量保持上游文件布局和实现；通过账号、凭据和设备上下文接入 usa0。
- **usa0 自有区：** OAuth/账户权益、托管模型与密钥、设备授权与路由、账户隔离、Cloud Chat/设备模式边界，以及品牌、Android 和发布部署入口。优先集中在少量模块，公共页面使用扩展入口。
- **品牌改动收口：** 面向用户的文字、资产、应用 ID、服务地址和更新/签名身份保持 ZeroAgent；内部类型、文件名、注释和目录不为改名而制造差异。
- **补丁必须有理由：** 每项说明对应产品需求、上游缺口、最小切入点和撤销条件。通用缺陷修复与 usa0 定制分开记录，上游有等价实现后撤销本地补丁。
- **衡量同步成本：** 关注修改了多少上游核心文件、增加了多少私有接口以及哪些差异需要反复解决冲突。纯粹减少总代码行数或合并补丁文件，不代表更容易同步。
- **旧版支持单独定范围：** “全新安装、不迁移/不回退”是上一轮讨论的精简选项，不是 usa0 定制的组成部分；不因旧实现而默认扩展兼容，也不把假设性讨论视为清除旧数据的授权。新版备份/同步功能单独评估。

目标是让后续同步主要变成“更新上游 + 检查少量定制接入点”，仍按精确发布版本保留 Git 祖先与验证记录；不承诺所有更新都能无冲突直接合并。

## 1. 必须保留的产品结果

| 边界 | 必须保留 | 可精简的实现形式 |
| --- | --- | --- |
| USA-Zero 账号 | OAuth、账户隔离、稳定安装身份、退出/切换账号撤销旧请求与凭据 | 收敛在 Native 会话及 profile 层，不复制到每个上游业务模块 |
| 托管模型与密钥 | 只使用 USA-Zero 托管模型；真实密钥受保护；显示/复制需近期二次认证；导出、日志不得绕过 | 保留 Native broker 和请求边界，模型执行采用上游；旧自建服务商归档随旧版支持范围决定，不能重新激活为模型 |
| 设备 Agent 与 Cloud Chat | 设备、工作区、租约、在线状态及撤销按账号授权；Cloud Chat 不获得桌面工具 | 设备路由外围适配，执行、审批、事件流交给上游 |
| 数据与旧版升级 | 账户历史/文件/工作区隔离；不自动导入其他产品数据 | 若支持旧版升级，保留显式迁移与回退；若选择全新安装范围，迁移、旧归档与旧格式兼容可整体退出，不维持旧执行引擎 |
| 配置正确性 | 私有字段不泄露、不被普通保存覆盖；并发保存/恢复不静默丢数据；设备写入落盘后确认 | 一个配置权威与必要的冲突检查；当前所有聚合协议、版本 DTO 和补偿层并非不可替换 |
| 支持端与交付 | Android 安全 OAuth/存储/更新；ZeroAgent 品牌、应用 ID、签名/更新身份；双仓库及 Gateway 镜像和就绪规则 | 使用上游公共 UI/构建骨架，保留平台与发布入口的小范围差异 |

主要落点为 `account_session`、`account_identity`、`desktop_oauth`、`managed_model_broker`、`backend_facade`、profile/迁移层，以及 Gateway 账号和设备授权层。不能用上游单实例 backend token 替换这些产品边界。

## 2. 可以采用上游的实现

| 能力 | 决策 | 边界 |
| --- | --- | --- |
| Agent 循环、模型协议、工具调度、审批、子代理 | `adopt` | 托管模型选择与凭据在外围适配；不保留第二套前端 Agent 循环 |
| session/run/event、SSE 恢复、ACK 查询、队列与执行历史 | `adopt` | 账号、设备、profile 和租约由 ZeroAgent 验证 |
| prompts、skills、memory、cron、goal 等执行引擎 | `adopt` | 使用上游实现和修复路径；已发现的失败继续记录，不能靠隐藏功能通过验收 |
| MCP 标准发现、搜索、工具执行与协议协商 | `adopt` + 窄适配 | 使用同一 Go MCP manager 和官方 SDK；适配 usa0 凭据及明确选择支持的能力，不默认继承全部旧实现 |
| MCP 配置/状态/重载 API | 优先 `adopt` | 固定上游已有 `/v1/mcp`、`/v1/mcp/reload`、tools/search；保留私有字段合并及配置冲突边界 |
| 公共聊天布局、资源页、设置页及通用组件 | 优先 `adopt` | 账号菜单、托管模型导航、平台能力用扩展入口接入；不整页复制 |

证据：当前 [`turn.ts`](../../crates/agent-gui/src/lib/kbrain/turn.ts) 相对目标上游只有两处品牌文字替换；8 个 Go 补丁没有改动 `internal/agent/` 或 `internal/ai/`。因此核心执行并未被全面重写，重点应转向外围。

“采用上游工具调用”不能理解为把任意原始调用直接开放给前端。固定源的 `tools.Authorize` 在缺少 gate 时不会主动拒绝；须核实实际会话审批上下文和 ZeroAgent 授权约束，不能把独立 `/v1/mcp/tools/call` 自动视为与会话执行等价。

## 3. 优先精简的三个部分

### A. 撤掉没有实际消费者的私有 MCP 控制面（第一优先）

已确认：

- [`host.ts`](../../crates/agent-gui/src/lib/host.ts) 固定启用 K-brain；[`builtinRegistry.ts`](../../crates/agent-gui/src/lib/tools/builtinRegistry.ts) 的旧前端工具入口在该模式下直接拒绝，生产源码搜索未发现其外部调用方。
- 旧 [`mcpManagerTools.ts`](../../crates/agent-gui/src/lib/tools/mcpManagerTools.ts) 仍引用 Native status/stop/test/restart，但当前共享 MCP 卡片没有这些操作入口。
- 新增 [`mcp_runtime.rs`](../../crates/agent-gui/src-tauri/src/commands/integration/mcp_runtime.rs) 只发送 status/stop/restart/probe；Go 私有路由还增加了 list/call，没有找到第一方生产消费者。测试调用本身不证明产品需要。
- 私有 `CallRich` 不在正常 Agent 工具输出链上，保留它并不能解决正常对话中的 MCP 富结果展示。

方案：先移除自定义私有 list/call；确认 status/stop/restart/probe 的完整调用链后，尽可能撤掉 `zeroagent.mcp-runtime.v1` 与 Native 转发层，状态/发现/配置复用上游接口。共享的取消、进程回收及凭据修复单独保留。

**不做机械删除：**旧前端 registry 和 Native transport 大量代码上游也保留着。对没有运行时影响的上游遗留代码，优先恢复/保持上游原样，避免为了减少绝对行数而制造额外分叉。优先撤掉的是本次新增的无用适配。

临时停止、重启、未保存草稿探测在固定上游没有完全等价 API。持久化禁用不能冒充临时停止；若仍有真实入口或必须保留的使用场景，再保留最小操作集，不整套保留私有协议。

### B. 收缩 MCP 历史容错范围（第二优先）

上游已有 MCP 与官方 SDK 版本协商；缺的是固定 K-brain factory 对经典双端点 SSE 的接线以及旧配置映射，不能笼统称为“上游没有兼容”。

协议能力以上游固定版本为默认范围。保留必要的 Native OAuth/凭据刷新；经典 SSE 与 `messageUrl` 支持是否保留，按明确的 MCP 服务支持范围判断，不能仅因旧实现存在而要求继续补齐。若不支持旧配置迁移，旧字段映射无需因数据兼容而保留。`/sse` 自动猜 `/message`、缺字段仍接受、逐个试探历史版本、为未证实服务器新增协议特例等，不作为本次同步必达目标；不再扩展。

已有非标准 fallback 的实际移除需先列出受影响旧配置与手动修正方法。只保存配置用于回退不等于当前运行链必须支持所有历史行为；也不能无记录地让既有 MCP 配置失效。

### C. 缩薄配置与 UI 适配（第三优先，分阶段）

当前配置涉及 Native coordinator、聚合 revision、HTTP ETag/If-Match、SDK 版本绑定、批量补偿、备份/恢复和设备 ACK。保留用户数据与冲突保护的结果，合并重复 DTO、协调入口和读写代理，尽量复用上游分域存储/API。

固定 K-brain 的 settings PUT 没有与当前保护等价的乐观并发检查，不能直接整层回退。聚合 `/v1/configuration`、跨域补偿等要先分别证明有必要；若采用更简单的分域保存/恢复设计，须先验证并发编辑、恢复冲突和写入结果不确定时的行为。此项是设计审查候选，不与 A 混成一次大删除。

共享 UI 恢复上游布局，保留账号、托管模型与端能力扩展。缓存图片加载、Windows 冷启动及进程清理等已复现的通用缺陷修复单独列项，不因其不是品牌代码就回退，也不借机扩展新平台特例。

## 4. 当前 8 个 K-brain 补丁的处置

按具体改动拆分，不能整包按名称删除。

| 补丁 | 建议分类 | 处置 |
| --- | --- | --- |
| 0001 Native MCP credentials | `adapt`，保留 | Native 安全存储/注入边界；缩薄桥接，不把真实凭据交还 renderer |
| 0002 Windows selfhost fixtures | `adopt` 候选，保留测试 | 测试基础设施，与运行时分开维护，适合上游化 |
| 0003 credential history / legacy SSE | `partial` | 保留凭据安全；SSE 接线按服务支持范围决定，把额外历史容错拆开审查 |
| 0004 private MCP runtime control | `replace` / `partial` | 优先撤无消费者 list/call，再审 status/stop/restart/probe；保留被其他链路使用的生命周期修复 |
| 0005 disabled OAuth diagnostics | `defer` / 删除候选 | 若仅服务已撤的草稿探测，一并移除；合法的 OAuth 授权入口仍保留 |
| 0006 explicit SSE message endpoint | `adapt` 或退出 | 仅在明确需要该端点能力时窄保留；全新配置范围不因旧字段而强制保留 |
| 0007 owned stdio / SSE cleanup | `adapt`，保留已复现修复 | 保留子进程树回收、取消及有界清理；上游有等价修复再替换 |
| 0008 inferred SSE message endpoints | `defer`，优先移出发布阻塞项 | 非标准端点猜测；实际删除前审受影响配置，不再追加变体 |

可把最终保留内容整理为“凭据、标准 SSE/旧字段、生命周期修复”三组，但补丁合并只是组织变化，不等于代码减少；不承诺零 Go 补丁。

## 5. 建议实施顺序与验收边界

1. **固定审查基线。** 保留现有工作区与补丁，不再加入兼容变体；将必须保留的结果映射到少量关键用例。
2. **先做 A。** 清理无消费者私有操作及其专属测试/文档，复用上游现有 MCP API；必要的 OAuth、profile、取消与生命周期修复不混删。报告实际删减行数及保留下来的差异。
3. **再做 B 和 UI 薄化。** MCP 以上游能力为默认范围，所选 transport 共用同一执行链。公共 UI 保持上游，账号/模型/设备通过扩展入口接入。若选择支持旧 LLM 配置，仅归档、不重新开放模型选择；全新安装范围不维护这套归档链。
4. **单独评审 C。** 配置层先简化设计再改代码，避免为减少分叉重新引入丢配置或泄露密钥的问题。
5. **先交付一个可验证的 Windows 闭环，再完成其余平台与发布检查。** 缩短每轮反馈时间，但 Android、Gateway 与跨平台验收仍是发布条件，不能宣称已完成。

实施后的必要验证按受影响行为选取：账号 A/B 隔离与退出撤销；托管密钥显示/复制/导出；设备选择、租约、取消；MCP ask/deny、OAuth、所选 transports、进程回收；并发保存及设备落盘 ACK。旧配置迁移/回退和新版备份/恢复分别按所选范围验证。已有测试覆盖同一结果时复用，不为每层代理重复造一套。

当前仍有完整产品验收及部分 backend 回归结果未闭合，不能把“改用上游”当作它们已经通过。这份审查只给出可执行的收缩顺序，不给出尚未实现的删减比例或完成承诺。
