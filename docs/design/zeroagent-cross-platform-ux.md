# ZeroAgent 跨端组件与交互规范

版本：1.7。更新：2026-10-31。基准：当前 CloudChat v1.13；决策：[ADR0058](../product/decisions/0058-cross-platform-design-system.md)、[ADR0059](../product/decisions/0059-workbench-composition-and-capabilities.md)。

## 新功能先设计再实施

新增和扩展功能先说明用户要完成的任务及完成后的结果，再设计入口、主流程、信息优先级、布局和关键状态。
不能从已有接口或解析库的演示界面直接拼出最终页面，再以统一圆角和颜色代替产品设计。
复杂功能的对应设计文档至少包含以下内容；小改动可简写在现有规范中，无需另建一套文档或审批流程。

| 设计内容 | 实施前应明确 |
| --- | --- |
| 用户任务 | 使用场景、入口、默认动作、完整完成路径、本次范围和真实能力 |
| 页面布局 | 桌面宽屏、被其他面板压窄后的画布、手机单列的布局与操作优先级 |
| 交互与状态 | 选择、打开、返回、继续工作、加载、更新、空、失败、无权限、取消及结果待确认 |
| 组件与状态归属 | 复用哪些共享组件，新增哪些业务组合，状态由谁持有，各宿主适配哪些能力 |
| 可评审结果 | 关键布局和状态的线框/原型或实际组件预览，以及对应的体验验收路径 |

设计与实现可以在推进中调整，调整后更新同一份方案。设计在已授权范围内自主推进；用户要求先评审时，
按要求先交付可评审的结果。复用开源编辑器、预览库或上游组件时，先确定产品体验，再用适配层接入现有设计系统。

2026-10-31 用户提供的参考体现了两类体验：豆包让对话与文档/表格并排，产物卡片可直接进入阅读工作区；
Codex 用右侧面板承载当前任务的工具和内容。参考其信息层级、内容优先、上下文连续和就地操作，
不复制第三方品牌、账号数据或装饰。ZeroAgent 的字体、颜色、圆角、密度、hover、Tooltip 和动效仍以本规范为准。

每次交付应让用户走通一条完整真实路径。后端接通、测试数量和构建成功分别记录，不能替代页面及交互的实际验收。
技术验证界面可以用于开发阶段，但在完成目标体验前应明确为未完成，不能据此宣称产品功能已交付。

## 基础视觉

所有宿主使用 agent-ui 的语义颜色、字体、图标、表面、边界、圆角和动效。以角色区分页面、
侧栏、控件底面、选中、悬停及浮层，浅深主题分别校准。不用页面缩放补偿字号或密度，不缩放动画中的文字。
主要阅读列沿用768px；宽工作区按内容扩展。桌面常用操作36px，紧凑工具允许32px；手机常用入口至少44px。
输入文字手机至少16px，正文/说明分别采用清楚层级，长名称先利用实际剩余宽度再截断。

按钮保留明确主次，普通操作不堆叠强阴影；输入采用轻边界和可见焦点。菜单和选择弹层采用
统一柔和表面、图标文字间距、视口避让与短透明度过渡。模态的焦点、Escape、关闭及遮罩由共享原语管理。
导航抽屉保持清晰浅遮层，不模糊背景。Tooltip 使用既有近黑胶囊和真实快捷键底面，展开菜单时让位。

## 交互状态

每个可交互组件明确默认、hover、选中、选中hover、focus-visible、pressed、disabled及busy。
hover不触发导航、保存或执行；聚焦不等于选择。禁用态保留真实disabled/aria-disabled和事件守卫。
主操作反馈不能模拟完成；加载、失败、待确认结果分开。未知写结果不自动重发，保留核对入口。
关键错误靠近相关内容/输入，不以跨全屏横幅代替；动作由业务宿主提供，提示不拥有重试权限。

紧凑提示按是否需要处理区分：纯进度与说明使用无背景状态行；有操作的提示使用轻量中性
表面，状态文字在左、处理入口在右，图标与内容对齐。主文案说明发生了什么，次行交代
输入是否保留。按钮使用轻量胶囊和清楚的悬停/焦点，窄阅读列和手机保持同一结构，触控
高度至少 44px；不能把按钮挤到文案下方后仍让图标按两行整体居中。草稿冲突持续保留
比较入口，不自动覆盖任一处草稿，也不因调整呈现改变保存和冲突处理逻辑。

## 导航和页面

应用轨、上下文侧栏和画布共用视觉语言。头像为账户入口，设置经账户菜单进入；所有已存在的
导航和功能继续可达。收起侧栏的临时预览不改持久偏好，不推移正文；固定展开时不做hover导航。
桌面窗口拖动区不得覆盖可交互控件。非聊天页面保留原聊天挂载及订阅，隐藏内容同时inert。

宽屏外框以侧栏和内容区为一个整体，应用轨留在外框之外；固定展开侧栏时不在内容区左侧再画一组圆角或边框。
整体外框使用共享18px圆角及细边界；临时侧栏使用16px圆角与共享浮层阴影，覆盖正文但不改变正文宽度。
侧栏菜单通过Portal呈现在预览层之上，统一14px字号、16px图标、8px条目圆角和36px鼠标行高；触屏至少44px。
外框装饰不接收指针事件，不覆盖窗口拖动、缩放或按钮命中区；展开/收起仍由原控制器管理。

设置使用一致的分类导航、标题、搜索、设置行和反馈。桌面可双列，手机分类/详情单列；
真实权限和已有配置项由宿主控制。文件、成果和本机资源可共享卡片/工具栏，资源身份和协议保持独立。
空、首次加载、更新、失败、无匹配和不可用分别说明下一步；刷新保留已知内容，避免闪空。

### 左侧导航调宽（2026-11-02）

用户可在桌面固定展开的聊天、资料、功能及设置侧栏右边界拖动调宽。边界采用 16px 透明命中区，
静止不新增装饰；hover/键盘聚焦显示细分隔高亮并使用 col-resize 光标，按下后持续高亮。
调宽连续跟手，不对拖动中的宽度做缓动，不改变现有展开/收起动效。释放后记住当前浏览器/宿主的
布局偏好；聊天、资料与设置共用该宽度，独立远程页面仍在自己的宿主范围保存。

默认 272px、最小 240px、最大 440px，且不超过可用宿主宽度的 40%，为正文预留至少 360px；
窗口变窄时只约束呈现，重新变宽恢复原偏好。双击或 Enter 恢复默认；键盘左右键微调 10px，
Shift 加速，Home/End 到边界。Escape、指针取消、窗口失焦或卸载撤回本次拖动；释放才持久化，
拖动不切换目的地、不重建会话/编辑器或改变草稿、运行与授权状态。跨 iframe 拖动保持捕获并阻止选中文字。

应用图标轨宽度保持固定。收起后的临时 hover 预览沿用已选宽度，但不提供调宽手柄、不固定展开，
移入/移出及预览菜单行为保持。手机抽屉继续按原视口和安全区布局，不继承桌面像素宽度、不显示调宽手柄。
侧栏内部内容填满实际容器宽度，不能保留旧的固定宽度或最小宽度。标题栏操作靠右对齐，项目与会话行随容器伸缩，
名称仅在实际剩余宽度不足时省略；滚动视口靠近侧栏右边界。验收须测量实际会话组件内部与外框的宽度，不能只验证调宽值。
验收覆盖宽窄桌面、资料/设置往返、收起预览、刷新恢复、拖动取消、键盘以及手机返回与草稿保持。

### 分隔边界的发现与重置（2026-11-02）

左右边界沿用同一交互：hover 显示细线高亮和共享近黑胶囊“双击恢复默认宽度”，
仅悬停不改变布局；按下拖动时隐藏提示，保持连续调宽。键盘聚焦同样可发现该提示，Enter 可重置。
双击只恢复当前分隔线，不重置另一侧、展开状态、会话、草稿、阅读位置或预览内容。
左侧恢复 272px；本机/远程右工具栏恢复 420px；CloudChat 对话/阅读分隔恢复初始的 44% 对话占比，
均继续受当前容器的最小宽度约束。手机抽屉与收起侧栏的临时预览不增加分隔线和重置入口。
多会话分屏仍按原规则均分，不把两类布局偏好互相覆盖。

## 对话和工作区

继续使用单一ChatComposerBar、模型来源和草稿。外观布局与云/本机/远程执行能力分开。
模型和思考采用同一视觉组合，选项来自真实宿主；支持的档位、参数保存、供应商与分组路由不变。
发送/停止使用同一个真实操作入口；队列、审批、安全模式、Git、语音和工作区功能按原条件显示。
附件和上下文统一轻量卡片、取消/加载/错误反馈，资料选择不自动发送。
起步卡片按聊天画布的实际宽度响应；桌面多面板压缩画布时采用可横向浏览的完整卡片，
避免仅依据窗口宽度强行保留三列。卡片仍只填入草稿，不自动发送。

消息、代码、工具过程、审批和成果遵守同一文字及表面层级。长内容、复制、编辑、分支、重试、
引用和下载继续走既有控制器。功能入口不能只为视觉简洁而删除。

资料与成果采用消息内卡片、上下文预览工作区和独立打开三种合理组合。桌面宽屏优先在对话旁打开内容面板，
让用户能继续提问或修改；手机进入完整阅读页并保留清楚返回路径。不能把所有资料阅读统一塞进通用操作弹窗。
文件类型决定阅读工具，宿主能力决定可执行动作；详细规范见 [资料空间体验规范](cloudchat-personal-space.md)。

## 手机和可访问性

手机单列、底部输入，菜单按可用空间选择浮层或Sheet；应用轨和上下文导航共用一个模态。
必要动作常显或有明确点击入口，不以hover/长按作为唯一入口。焦点、读屏名称、错误语义与键盘操作保持。
会话行常显至少44px的“更多”按钮；点按直接打开原管理菜单，长按仍可使用。运行标记与按钮并存，
进入多选后隐藏普通管理入口；运行中、忙碌或无权限时继续遵守原有操作限制。
安全区与键盘高度沿用Native桥/visualViewport，不增加第二份高度状态。系统返回先关闭内层、再返回页面。
内层浮层沿用 Escape 的关闭守卫和焦点归还；禁止关闭时不能穿透到背景页面。手机设置先从详情返回分类，
未保存的项目仍须确认放弃，返回操作不得取消运行中的任务或清除草稿。
手机和平板的软键盘回车换行，发送使用明确按钮或 Ctrl/Command+Enter；窄桌面窗口继续遵循原本机发送快捷键偏好。
支持减少动态、强制颜色、系统字号和缩放。鼠标使用手型、文字使用I型，拖拽/缩放保留专用光标。

## 维护和验收

工作台统一消费 `WorkbenchShell`，分栏工作台用 `WorkbenchBody`，页面及设置用 `WorkbenchCanvas`。
外框圆角、边界和手机收边由共享样式负责，宿主不再另外覆盖一份。导航图标与功能定义来自
`workbenchNavigation`，品牌来自 `BrandMark`；导航目的地、快捷入口偏好和回调仍由宿主提供。

输入栏的 `presentation` 表达画布几何，`capabilities` 表达可呈现的能力，两者不得互相推导。
本机分栏采用 pane，设备 WebUI、内嵌远程和 CloudChat 阅读列采用 column；这两种组合复用相同控件、
动效、表面和交互。云端关闭设备执行、Git 与本机目录入口；设备工作台保留这些入口原有的可用性条件。
前端能力声明不能代替服务端授权、设备租约或原生凭据检查。

设置复用 `SettingsWorkspace`。宿主轨道可以通过 `WorkbenchNavigationMount` 移入，后台保留宽度占位；
CloudChat 保留外部轨道，两种方式均只显示一个账户入口。会话树保持挂载并在后台 inert，不能因为换外框、
设置往返或切换功能而重建草稿、队列、订阅或模型控制器。独立桌面远程工厂继续隔离加载与释放。

应用更新入口在左侧应用轨底部、头像上方，使用同一蓝色下载图标与黑胶囊提示；不放到
标题栏或会话列表脚部。手机入口至少44px，点击展开详情；自动发现不弹窗打断，“稍后”
保留入口。桌面安装与重启继续由原宿主控制器处理，远程工作台通过宿主插槽呈现。
普通浏览器不显示 App 原生更新。UI 调整默认采用 Web 桌面/手机视口验证，不逐次构建
App；系统安全区、IME、系统返回和下载安装等平台链路仍须单独记录原生证据。

共享变量和组件为唯一视觉来源，宿主仅保留布局/能力适配；不复制CloudChat组件到各端。
每批验证实际消费页面，涵盖浅深、宽窄、键盘、鼠标、触控、长名称与失败恢复。样板展示全部
控件状态以便持续检查；相关回归保护草稿、IME、选择范围、保存、账户和设备边界。
GUI/Web/嵌入Android/独立远程工厂分别编译和挂载；真机及原生窗口交互必须另外验收。

共享控件样板位于 [design-system-browser](../../crates/agent-gui/test/design-system-browser/README.md)，
直接渲染真实组件，提供浅深主题、字号比例、宿主能力、表单、菜单、弹窗、反馈、资源和模型/思考检查。
样板不挂载账户或执行客户端，不作为原生交互或在线设备验收的替代。鼠标 hover、键盘焦点和真实触控分别记录，
改变浏览器宽度不代表已获得触控输入或原生键盘。
