# 文件运行时与阅读器批注

用户可以从对话创建文档、PDF、电子表格和演示文稿，也可以在原阅读器选择内容、汇集批注并发送。设备工作台使用共享阅读器与消息摘要，CloudChat 通过自己的文件版本和发布回执完成同一任务。

桌面保留对话与右侧阅读器并排的布局。窄屏先在阅读器内完成选择和评论，再返回同一对话查看「N 条注释」。批注可逐条定位，编辑、取消和提交沿用阅读器的当前文件与草稿。工具执行出现在实际对话过程里，成功后回复附上已验证文件，失败时说明无法完成的具体操作。

工具读取执行工作区中的文件引用。工作区从现有设备执行权限或云端隔离环境获得，技能正文不授予额外权限。编辑请求绑定读到的 SHA-256。每次执行在工作区临时目录完成并重新打开结果，确认源版本后才发布新文件。工作区原件写回和云端版本发布继续经宿主各自的授权入口完成。

安装验收覆盖 Windows x64、macOS x64/arm64 和 Linux x64，使用与候选版本配套的依赖在离线环境执行。发布验收同时覆盖同一设备会话的三种入口及实际 CloudChat 候选镜像。

## 内置技能包

设备 Skills Hub 和 CloudChat 目录显示「文档」「演示文稿」「PDF」「表格」，复用对应文件类型图标，统一标为内置。界面名称用于搜索与显示，执行保留稳定技能标识。启动时撤下已知的旧内置修订技能，保留其目录备份，普通用户技能仍按现有规则发现。

设备和 CloudChat 以 `crates/agent-gateway/internal/account/skills` 下的四个内置目录为唯一来源。每个目录的 `SKILL.md` 是完整工作流，直接加载同目录的参考资料、脚本和模板。工作流基于 Codex `26.1110.11258` 的本地文件技能，各包保留 MIT 许可。宿主适配涵盖运行时解析、授权文件、批注、进度和交付。Google Workspace、Excel 实时控制和 Codex 的操作状态标记属于其在线集成。

阅读器传递原文件及其批注锚点，普通对话与阅读器使用同一套技能入口。桌面原生和远程设备使用目标设备的文件与运行时。CloudChat 从账户工作区加载指定版本，验证后经原有资料发布入口交付。确定性的定点改稿可使用带源版本检查的文件工具。需要完整工作簿或演示文稿对象模型时，工作流直接加载随附的 Artifact Tool。

## 桌面文件工具按需初始化

Windows x64、macOS Intel、Apple Silicon 和 Linux x64 安装包提供登录、对话、阅读器及设备控制。首次需要修改文件时，如果当前电脑的文件工具尚未就绪，阅读器在原批注区域给出准备入口。用户可在「设置 → 系统设置 → 工作区工具」提前安装，也可继续阅读或编辑批注。窄窗复用同一设置行和原位提示。Windows 沙箱继续走命令安全设置的现有流程。

设置行显示已验证版本、下载体积、下载进度、校验、待启用和可重试的错误。用户主动选择准备或修复后，原生宿主才下载，或读取用户明确选中的离线安装包。切换对话或收起设置时，本机继续准备。阅读器在原处保留批注，完成后由用户重新提交。用户从阅读器进入准备时，已保存对话的批注按账户、对话、工作区、文件路径和内容摘要暂存于本机。重开原对话中的同版本文件可恢复批注。未保存的新对话在重启前提示复制批注。远程 Web、Android 和桌面远程使用现有授权设备状态，提示到实际执行的电脑完成准备。

发布工作流从锁定的独立上游组件组装和验证各平台的文件工具，只把小型描述清单纳入主应用。清单通过官方签名应用交付，固定目标、版本、下载位置、字节数和 SHA-256。公开 Beta 和正式版指向对应的公开 Release 资产。Alpha、RC 和 `artifacts_only` 构建均可导入同一工作流生成的工具 ZIP，应用通过内嵌摘要验证用户选定的文件。基础验收是 Word 定点改稿、PDF 定点改稿和 Word 转 PDF。Windows 工具包通过 openpyxl 和 python-pptx 提供标准表格与演示文稿操作。macOS 与 Linux 保留独立包内的 Node.js 和 Artifact Tool。已安装的受管版本和显式开发运行时可以继续使用。

原生安装在应用管理目录暂存，限制下载和解包范围，拒绝路径穿越、链接和摘要不符。通过文件工具探测后再记录候选目录，保留先前版本。当前 K-brain 仍使用启动时绑定的工具路径，新版本在按应用已有退出流程完成重启后启用。初始化失败或安装包损坏时继续使用上一版。验收覆盖明确同意、取消选择、网络中断、损坏包、重试、并发请求、重启切换、离线改稿和远程切换设备。

「工作区工具」内分行显示启用开关、诊断、安装或重新安装、移除。桌面与窄窗沿用共用设置行和破坏性操作确认。关掉开关后重启停止向引擎提供文件工具，已安装的包可在重新启用后继续使用。诊断刷新就绪结果。移除确认后转为待重启，完成既有退出流程后由原生应用清除自己管理的版本和未完成的下载，文件工具随后保持关闭。正在使用工具的进程或清理失败会保留待处理状态。原件、已保存的批注、用户手动选入的 ZIP、系统及开发工具留在原位。远程端只读取所选设备的就绪状态。

开发目录和旧版随附工具就绪时显示来源。没有配套校验清单的构建保留安装行，并说明该构建无法安装或重新安装。对外部工具可确认解除关联，重启后停止使用，来源文件保留。通过校验的应用管理版本在重启后优先绑定，开发目录和随附资源可在缺少应用管理版本时补位。

## 运行时

开发启动、正式安装版和便携版共用清单格式及文件工具。所有受支持的桌面平台使用同一套按需初始化流程。Android 和桌面远程工作台读取所选设备的就绪状态。阅读器发送前向实际执行的设备核对其运行时，失败在原批注区域反馈，保留全部批注、当前文件和输入焦点。重试仍检查同一对话与授权。缺少运行时时仍可阅读文件和撰写批注。

桌面发布工作流按同一源码提交调用 `file-runtime-packs.yml`，在目标架构的 Windows x64、macOS Intel、macOS Apple Silicon 和 Linux x64 运行器上组装依赖。各平台的依赖锁固定上游下载和 SHA-256。构建保留许可声明，并生成格式为 1 的 `runtime.json`，记录版本、来源、逐文件摘要和入口。验证通过后把压缩包及收据保存到同一次运行的 Actions 产物中。每个目标交付一个独立安装 ZIP，将摘要写入对应签名应用。POSIX 平台在归档和解包时保留可执行位。

文件工具的测试与实际离线改稿使用全新用户目录。离线验证在 Linux 使用独立网络命名空间，在 macOS 禁止 IP 套接字并保留 LibreOffice 启动所需的本地管道，在 Windows 对工具包内可执行文件临时设置出站阻止规则。Windows 无界面工具包保留英语拼写词典和中英文 LibreOffice 界面翻译，减少空白配置首次初始化时间。Windows 发布先解出工具 ZIP 验证离线处理，再检查 MSI、NSIS 和便携包的安装或启动，以及各包是否省略文件工具。可以在不创建标签的情况下用 Desktop Release 工作流的 `artifacts_only` 验收候选。桌面依赖升级通过变更锁文件并重新验证，回滚沿用旧提交和对应发布包。开发者仍可显式配置本地依赖树或内部包索引。

本地 `node scripts/dev-stack.mjs restart desktop` 及调用它的 PowerShell 启动脚本继承同一配置。可用 `ZEROAGENT_DEV_FILE_RUNTIME` 指定运行时目录，或在没有指定依赖包时使用当前检出的 `.zeroagent/file-runtime/desktop-dev`。本地清单格式为 1，包含目录内的 Python 路径及已准备的附加工具路径，文件工具位于同目录的 `tools/`。附加引擎可按开发任务补齐，调用缺少的引擎时报告具体组件。宿主把当前已验证运行时的绝对路径注入实际运行的 K-brain 子进程。

候选检查分别验证各平台独立工具 ZIP 和主安装包。主安装包的文件清单须省略工具树，并保留可用的应用、更新签名和对应工具描述清单。macOS 继续通过 `hdiutil` 生成包含 Applications 快捷入口的 DMG。Linux AppImage 继续移除不需要的 Wayland 库，然后重新签名。测试进程使用全新的用户目录、隔离的 PATH 和 Python 网络审计钩子，验证 DOCX 段落改稿、PDF 定页改稿、PDF 渲染和原件不变。随后通过文档技能的渲染脚本，用包内 LibreOffice 导出两页 Word 改稿，并通过包内 Poppler 逐页渲染。检查记录解释器与 LibreOffice 的实际路径，核对导出 PDF 的页数、修改文字及未修改页。测试原生子进程的离线运行需要在禁网环境执行。三种设备入口的阅读器和真实模型执行仍需单独验收。

CloudChat 模板从同一目录打包技能及工具，锁定 Office、PDF、OCR 和图片格式转换依赖。Linux x64 依赖层提供 Node.js 24.22.1、Artifact Tool 2.8.145 和原生 Skia。候选计划包含 SDK 生成的内容摘要。

## 当前验证记录

Windows x64 按需流程的发布配置、安装器契约、原生 ZIP 验证及阅读器准备交互已通过针对性测试。新的运行时自检在已有 Windows 隔离运行时样本上验证了 Word 定点改稿、Word 转 PDF、PDF 批注和渲染。新组件组合的真实 ZIP、应用导入后的整机断网检查及新安装包体积仍待隔离验收。

Windows x64 通过了桌面技能安装和升级测试，并用本机的 Node、Python 与 Poppler 直接验证了 PDF 提取与渲染、文档修订、演示文稿渲染和模板检查，以及表格原生对象。Linux x64 在禁网容器通过四种格式的工具验收，覆盖文档逐页渲染、扫描 PDF OCR 与涂黑、Office 转换与公式重算、原生数据透视表和双变量模拟运算表。

DOCX、PDF 改稿与 Word 渲染检查已在 Windows x64 测试目录及 Linux x64 禁网容器通过。两者使用新的用户目录、测试目录中的 Python 和 LibreOffice 26.2.7。Windows 使用 Python 3.12.14，测试副本保留英语词典，移出其他可选词典后通过首次初始化。Linux 使用 Python 3.12.16，容器仍提供系统共享库。Windows 验证了 Python 网络审计与隔离用户目录，仍需在整机禁网环境验收 MSI、NSIS 和便携 ZIP。

本地 Windows 开发运行时使用目录内的 Python 3.12.14，通过 DOCX 和 PDF 定点改稿及 PDF 渲染检查。开发清单未启用此前测试超时的 LibreOffice。新的测试副本与开发目录独立。

单变量模拟运算表可写入 OOXML。本地 LibreOffice 回写样本时将它改写为普通公式，未写出有效的结果缓存。该路径不能作为单变量模拟运算表的验收依据。

CloudChat 当前验证覆盖 Gateway 技能读取与本地候选配置序列化。三种设备工作台的同一会话、各平台安装包与便携版首次离线运行、macOS Intel 和 Apple Silicon 实机，以及实际 CloudChat 镜像仍待验收。
