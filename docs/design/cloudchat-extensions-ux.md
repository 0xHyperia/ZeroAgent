# 插件与技能：ChatGPT 体验调研及 ZeroAgent 设计方案

日期：2026-11-04。代码基准：`9c9ba988`。

状态：**2026-11-05 已实施 CloudChat 目录、账户技能生命周期、阅读及会话引用；第三方连接与跨端 Hub 统一尚未完成。**

## 2026-11-06 会话引用与详情

录屏前六秒的插件引用与文字同一行，可随文字选中，悬停时可识别为详情链接。点击打开插件详情，保留会话和草稿。键盘可聚焦并激活引用，手机可点按。独立技能直接打开正文。插件详情保留技能数量、展开和阅读入口，包内技能的阅读器提供关闭动作。

`@`、添加菜单和工作栏以已启用的插件及独立技能为单位选择，`/` 只列独立技能。目录搜索保留中英文名称。展示名称跟随应用语言，应用语言默认采用宿主首选的受支持语言。个人和第三方自带名称沿用作者提供的名称，技能正文、文件路径、旧草稿引用与版本固定规则保持原样。

本节更新 ADR 0071 的会话候选范围和 ADR 0076 的固定英文名称展示规则。归档及执行契约继续适用。

内置名称、列表摘要、详情介绍和技能说明使用同一套界面语言，搜索同时匹配中英文。个人和第三方的说明保留作者原文，试用提示词及技能文件沿用发布内容。

录屏末段的应用详情按实际能力适配。插件详情中的应用行可打开说明，并呈现本地入口或托管应用的连接状态。

## 2026-11-06 技能正文优先与 Design QA 交付核验

插件详情打开具体技能时直接阅读该技能的正文。桌面按用户提供的 Skill Creator 参考恢复双栏。
左侧文件树把正文放在首行，并按真实路径组织可展开的目录。右侧显示 Markdown 或只读源码，

包内其他技能由插件详情各自打开，原文切换和返回正文仍然可用。

Design QA 增加可执行的核验步骤、严重程度和报告结构。基准与实现均需有实际可比的视觉证据，

使用 ZeroAgent 私有站点和用户提供的截图等真实证据，按条件保存验收记录。

## 2026-11-05 按 ZeroAgent 工作流程适配四个内置能力

目录与对话使用 ZeroAgent 自有工作流。创建技能或插件时，对话先明确触发场景和交付要求，
生成经服务器校验的草稿。回复中的草稿卡片打开现有编辑器。用户可检查文件、继续编辑，
再明确保存到个人目录。桌面沿用左侧导航与编辑画布，手机沿用单列编辑和返回。
打开时保留原对话输入及未保存的手工草稿。加载、草稿不可用、目录冲突及结果待核对
沿用现有反馈和保存保护。插件草稿支持多项技能和参考文件，已有个人包可基于明确的版本提出更新。

Product Design 用用户附件、公开研究、内置原型模板和隔离工作区完成证据、设计和可运行交付。
已保存的原型用现有私有站点阅读区预览，工具条增加「适合窗口」「手机」「桌面」视口选择。
窄窗口中的固定桌面视口允许横向滚动，手机不显示新的侧栏。用户在实际预览上继续批注；
只有确认完成的核验才写入交付说明。外部浏览器自动核验或设计应用按真实宿主能力提供。

Image Gen 沿用账户默认模型、成果画廊和参考图编辑。用户要求透明背景时向供应商传递参数，
并核验返回图片有真实透明像素。失败在原对话中就近说明，保留原件和当前任务。无模型或服务时
沿用已有配置引导。模型、验证与分享仍由对应的 ZeroAgent 工具处理。

[ADR 0077](../product/decisions/0077-cloudchat-native-extension-workflows.md) 记录当前适配。

## 1. 结论与目标边界

### 2026-11-05 用户再次修订：@按插件选择、行内引用贴合及四个能力重新设计

本节优先于上一轮仅在加号中列主入口、沿用立体图标的设计。用户给出三张原尺寸3360×1860截图，
并明确要求@直接使用插件、输入引用的图标和字体对齐参考，以及重新设计四个内置能力。
本轮实看已登录ChatGPT当前@菜单及Figma引用：候选36px高、14px/20px正文、6px/8px内边距；
输入16px/26px、400字重，引用标签500字重、普通inline文字，16px图标置于inline-flex/vertical-align:middle槽位，
图文3px间距，标签和后续文字共用基线，无背景、额外行内边距或缩小字。录屏物理像素不等同CSS尺寸。

用户任务：在当前文字中输入@，选择一个已安装插件，继续写需求；也可进入真实资料/项目选择，
不被插件内的全部技能淹没。@根菜单由宿主明确提供资料动作及每个已安装/启用包的一个主入口；
公开和个人均适用，独立技能各占一个条目，包内技能不展开。中文和原名搜索；/保留显式技能入口。
只选择主技能已启用的包，不能借主入口绕过该技能的停用。固定引用、剪贴板、账户校验和已发历史保持。
已有同包旧引用不替换为新版；新增候选仅准备引用，不发送、不调用模型。

共享MentionComposer增加可选的宿主能力候选和动作；CloudChat显式传入，设备默认的文件/应用/会话@模式保持。
候选紧贴输入框下方、同宽，空间不足自动避让，键盘上下/Enter/Tab选择、Escape关闭；手机44px行、内部滚动。
@中的照片/资料库/项目动作复用已有控制器，移除本次@查询后打开，不清空其余草稿。
菜单与加号的已安装能力来自同一目录定义，禁止复制第三方应用名作为假能力。

行内引用改用共享样式：标签继承输入字体、字号、行高，500字重；品牌图标独立16px、3px文字间距，
主体display:inline、基线对齐，保留真实键盘原子选择及删除。不能再让图像参与items-baseline的flex基线计算。
浅深使用参考的低饱和蓝色；不覆盖用户字体偏好。至少验收中文/英文标签、前后混排、换行、选择、复制粘贴、
删除、旧草稿恢复和手机。字体跨宿主回退要注明，不能仅凭CSS值声称字形逐像素一致。
插件选择、结构化粘贴和原子删除等直接DOM编辑必须发出与键入一致的冒泡input事件，通知宿主捕获完整草稿；
不能只在空态变化时保存，也不能把setDraft/setText加载及临时语音文字当作新编辑。验收必须包含选择后不再键入、
复制旧引用后不再键入，各自刷新恢复；保留原文字及固定引用。

四个内置能力采用清楚的任务定位、中文说明及三个真实起步提示：创建插件（组织一组相关工作）、
创建技能（沉淀一个复用方法）、产品设计（理解/探索/实现/核验）、生成图像（描述/参考修改/比较）。
新的品牌方向以用户图中的小尺寸清楚标识为准：透明底、简洁平面几何、有辨识度的蓝/暖金/紫红/青色标记，
无银色浮雕、重阴影或整块珐琅底板。16px行内直接使用标记，52px详情在统一白/深色圆角容器内展示。
使用原创真实资产，不手画SVG、不冒用Figma等第三方标志；同一资源贯穿全部入口。
详情保持现有共享结构，补足四类各自用途、输入与交付说明，仍只展示真实可用技能与应用配置。
内置工作流中文化并补足完整交付和失败恢复；如修改指令，必须保留旧定义并创建新的内部发布定义，
原固定引用继续读取原内容，产品界面不引入V1/V2流程，不迁移或删除用户数据。

验收：当前@前后截图；插件主入口及子技能不混排；中英文搜索及禁用过滤；动作不改原草稿；
引用的实际文字/图标边界测量与参考局部对照；四类详情与阅读；浅深、窄桌面、390px手机；相关行为回归和双前端构建。

### 2026-11-05 列表一致性与完整流程复验

#### 侧栏间距补正（用户再次指出间距问题）

前轮仅统一按钮状态，尚未统一列表容器；本节替代“容器布局已统一”的过宽结论。
任务仍是从分类进入目录或直接打开已安装插件，保留所有导航、草稿和安装状态。
桌面侧栏改用共享 `SidebarHeader`、`SidebarContent`、`SidebarGroup`、`SidebarGroupLabel`、
`SidebarGroupContent`、`SidebarMenu`、`SidebarMenuItem` 和 `SidebarMenuButton` 完整组合。
沿用现有导航的12px侧边距、10px行内边距、10px图文间距、36px最小行高与8px圆角；
两个菜单均使用共享间距刻度4px，组间16px，标签28px占位。不再使用局部段落的26px/14px上下外边距。
分类16px图标在20px槽位内居中，与20px插件标记占位相同，所有行文字起点一致。
打开已安装插件详情时仅高亮该插件条目，目录分类保持普通态；未安装插件没有侧栏条目时才高亮其分类。
标题栏沿用10px上/12px左右/8px下内边距、32px紧凑返回按钮及17px标题。
手机继续使用现有44px顶部导航，不将桌面侧栏压缩进去。验收同视口前后对照、实际边界测量、
插件/技能/详情往返、键盘焦点、窄桌面、浅深主题与手机返回；仅静态间距调整不新增业务状态或测试协议。

用户本轮要求修复剩余19项Web回归，并核查统一组件。自定义导航的悬停与选中使用同一背景，
鼠标停在另一分类时形成双高亮。分类、已安装插件及文件导航改为复用共享 `SidebarMenuButton`，
仅保留容器布局；选中以 `aria-current` 表达，悬停、按下、选中、焦点由共享组件区分。
插件和独立技能目录共用 `ExtensionDirectoryItem`、语义列表、菜单及状态来源，长名称和说明可查看完整内容；
不将资料选择卡片的开关交互套入浏览目录。
桌面36px与手机44px、图标文字10px间距、长名称省略及可访问完整名称一致。
空状态区分“尚无个人内容”和“当前搜索/安装筛选无结果”；读取失败不伪装成空目录。
导入或保存成功后展示个人来源、清除旧搜索及安装筛选，使刚完成的条目可见。

复验按“目录/来源与安装筛选 → 详情及文件阅读 → 个人创建编辑 → 启停卸载重装 → 原草稿引用 →
实际应用配置往返”推进，覆盖浅深色、宽窄布局、键盘、加载/失败/空状态。应用仅验证实际存在的
生图模型配置与宿主入口，不伪造外部连接或将第三方授权称为已验收。原会话、草稿和运行保持。
从ImageGen进入配置时，设置返回明确标为“返回 ImageGen”，回到原详情、来源与筛选上下文并归还焦点；
普通账户设置仍回到原对话。返回来源只属于当前账户、当前页面寿命，切号或从其他入口离开后失效。
图像创作设置允许直接打开和刷新恢复。CloudChat设置隐藏设备专属Skills/MCP配置，设备工作台仍保留原入口；
账户技能统一从自定义进入，尚未接通的云端应用连接不以设备设置充当入口。
图像设置响应中断或格式无效时，界面给出可执行的中文反馈，不展示浏览器解析异常。
读取失败可刷新重试；保存响应未确认时要求先刷新核对，不把结果未知当作保存失败并自动重试。
错误处理仍须校验请求所属账户，不因反馈改写而接受过期账户的响应。

## 3. ChatGPT 的设计为何成立

### 3.1 每一层只解决一个问题

- **目录**回答“能帮我做什么”：分类、图标、名称、一行说明和一个尾部操作。
- **详情**回答“是否值得安装”：真实示例、用途、包含的能力、发布者和数据使用信息。
- **管理**回答“现在允许它做什么”：安装、连接、各项能力的启用状态及卸载。
- **技能阅读/编辑**回答“它具体如何工作”：文件结构、指令和修改入口。
- **输入框**回答“这次任务要用谁”：搜索、选择和行内引用，不迫使用户再进入管理页。

目录没有把开关、分类标签、版本、权限、安装来源和诊断状态全部摊在条目上。
页面靠留白、对齐、字重和分组形成层次；高饱和色主要留给品牌图标和少量状态。
插件详情中的示例可以把用户带回任务，介绍页因此也是开始使用的入口。

### 3.2 插件、技能、连接分工清楚

插件是可安装的能力包，可以包含技能、MCP 工具及可选交互界面；技能是带有指令和可选
参考资料/脚本的工作方法；MCP 是工具连接方式。它们不是三个互不相关的功能中心。
这一关系也见 [官方插件概念](https://developers.openai.com/plugins/concepts/plugins)。

安装能力包和授权外部服务是不同动作，卸载插件也不等于撤销服务连接。
ZeroAgent 应明确显示并分别处理这些状态，不能用一个“已安装”勾号代替可用性。
参见 [官方插件使用说明](https://learn.chatgpt.com/docs/plugins)。

### 3.3 使用时逐步展开

默认只把技能名称和说明提供给模型，确实需要时再读完整指令和参考文件，可避免将所有
技能正文堆入每次请求。技能包以 `SKILL.md` 及可选资源组织，具体流程见
[官方技能说明](https://learn.chatgpt.com/docs/build-skills)。
ZeroAgent 的技能引用必须携带稳定身份，不能只插入一句提示词或从名称猜测所选技能。

## 5. 建议的信息架构

主入口使用与资料空间、对话相同的应用外壳，新增“自定义”上下文工作区：

```text
应用轨 → 自定义
           插件 → 目录 / 搜索结果 / 插件详情
           技能 → 已安装 / 搜索结果 / 技能详情
           已安装 → 用户常用的插件快捷入口

插件详情 → 在对话中使用 / 管理
管理 → 同一设置工作区中的插件设置及服务连接
技能添加 → 通过对话创建 / 使用编辑器创建 / 上传技能
对话输入框 → 插件与技能选择 / 行内引用 / 按需补齐配置
```

不引入角色、分组运营、组织审批或审计管理系统。已存在的设置项和设备入口继续可达，
不因界面重组而删除。自定义记住最后访问的位置；打开它不卸载正在运行的聊天。

### 5.1 插件目录与详情

目录页顶部采用标题与一句说明，右侧搜索、管理和主操作“添加”。主区为适度限宽的双列
紧凑条目；只有一列放得下时自然降为单列。品牌图标、名称、摘要与尾部动作跨行对齐。
点击条目打开详情，点击加号仅开始安装，两者事件独立；已安装条目的次要动作进入菜单。
分类不做花哨卡片墙，搜索时保留搜索框和页面骨架，明确区分无匹配与读取失败。

详情页顺序为：面包屑 → 品牌及主操作 → 可用示例 → 用途 → 包含的技能/工具 → 信息。
示例使用有明确点击反馈的任务按钮。图片缺失时使用统一图标占位，不能留下破图。
无需连接的插件安装后可立即试用；需要外部服务的插件显示真实连接步骤和恢复入口。

### 5.2 技能列表、详情与编辑

技能列表沿用插件条目，显示名称及一行摘要；默认不常驻版本徽章、路径和多个按钮。
尾部菜单只包含真实可用动作：在对话中使用、编辑/查看、下载、卸载，按来源与权限裁剪。
系统内置只读技能与用户创建技能共用组件，但不伪造可编辑或可卸载能力。

桌面详情采用宽阅读窗口：左侧文件树，右侧 Markdown/源码，底部试用入口。
有代码的文件复用现有源码预览器及语法高亮；路径、版本、文件内容均来自实际技能包。
查看文件不执行脚本。完整名称在截断后用共享 Tooltip 显示，菜单展开时不叠加 Tooltip。

编辑使用完整工作区，主要部分为名称、说明和指令；附属文件在文件树中维护。
创建/保存始终就地校验，保留失败内容。未保存修改离开时保护草稿；保存采用版本校验，
遇到其他页面修改时不覆盖。创建成功后更新目录并可直接带技能引用回到输入框。

“通过对话创建”只准备可编辑草稿和创建技能的明确意图，不能自动发出模型请求。
模型生成的技能先进入可检查的草稿，校验、安装后才成为可调用版本。

### 5.3 会话内使用

输入区域的“插件”入口提供已安装能力搜索及选择，“连接插件”位于列表底部。
显式技能引用沿用共享 MentionComposer：小图标、名称和文本同基线，不使用大块卡片。
引用可键盘选择和删除，IME 输入、粘贴、撤销、草稿恢复及跨页面返回保持完整。
项目、附件、模型和思考程度与能力选择各自保留，不因打开目录或授权页而重置。

插件级选择表示这次任务允许发现哪些能力；技能级引用表示用户明确指定的方法。
它们都不直接授予新的服务权限。展示名称重命名后，已发送消息仍能解析原绑定身份。
用户没有显式选择时，可根据安装及启用范围自动发现；读取完整技能仍按需进行。

缺少连接或默认生图模型时，在当前任务附近显示单一主动作“连接…”或“设置生图模型”。
跳转配置后返回原对话/原草稿；正在运行的任务是否可恢复由真实运行协议决定，
不能在配置返回后擅自重复调用可能收费或写入的工具。

### 5.4 执行与结果

沿用现有 AgentRun、工具记录与成果展示，只把对用户有价值的状态露出：正在读取、
正在处理、需要连接、已完成、失败及结果待核对。状态属于对应调用，不用独立演示假进度。
技能指令的读取和工具的执行分开记录；引用了某个技能不代表它已经执行成功。

图片、站点、文档、表格继续进入现有资料空间与预览器；会话里保持统一成果卡片和画廊。
图片加载保留最终比例、完成后平滑显现，失败不丢失用户描述和参考图。
外部插件需要交互界面时使用受限工具面板；未接通真实交互的插件不得展示可点击空壳。

| 字体 | 使用共享字体层级，条目名称与说明形成对比；菜单 14px、图标 16px，不通过整体缩放压小 |
| 表面 | 页面安静，默认条目无厚描边；hover 使用轻中性色底，选中与选中 hover 有可见差异 |
| 按钮 | 主操作黑白胶囊；普通图标操作轻背景；危险动作只在操作区及确认中使用警示色 |
| Tooltip | 近黑胶囊、清晰文字，快捷键单独浅底胶囊；完整名称与真实快捷键；不与菜单争抢显示 |
| 首次加载 | 与最终行列几何一致的骨架；搜索/刷新保留已有内容，局部 busy，不反复闪白 |
| 菜单/弹层 | 共享 Portal、避让、焦点管理及 Escape；建议 120–160ms 透明度及微小位移过渡 |
| 工作区切换 | 建议 160–200ms 连续过渡；保留原挂载及滚动位置，输入文字不缩放 |
| 安装反馈 | 行内操作变真实 busy，阻止重复提交；成功原位变“使用/管理”，不制造整页跳动 |
| 减少动效 | 遵从 prefers-reduced-motion，移除位移及持续装饰动效，保留即时状态反馈 |

每个条目和控件覆盖默认、hover、选中、选中 hover、键盘焦点、按下、禁用、busy。
hover 不能导航或执行；可交互区域使用相应指针。菜单条目内部文本不另加悬浮移动动画。
长名称先占满可用空间再截断，尾部按钮不能预留过宽空白。条目主操作与菜单互不误触。

## 7. 手机与多端适配

手机目录单列；标题、搜索和添加分行但不重复。上下文侧栏用现有抽屉，沿用浅遮层、不模糊。
插件详情主操作允许换行；技能文件树改为文件选择面板，正文全宽，避免两列挤成窄缝。
编辑器使用“基本信息 / 指令 / 文件”的分层进入，返回保留光标、滚动及未保存内容。
会话能力选择使用底部面板，搜索、勾选和关闭可单手操作；无需依赖 hover 才能发现菜单。

桌面、本机远程、Web、Web 远程和移动端共用展示组件及动作契约。适配器提供可用能力、
资源作用域、认证及实际执行目标。设备技能仍在相应设备执行，云端用户技能仍在用户云端作用域。
同名技能不静默合并；只有需要用户决策时才显示“此电脑/远端设备/云端”等位置说明。
只读、无脚本执行或不可安装的宿主显式提供对应可用动作，不假装各端能力完全相同。

## 8. 支撑体验所需的最小架构

保留现有 PostgreSQL、Redis、对象存储和 E2B，不为插件中心另引入一套应用栈。
以下是职责方案，具体表及接口在实现时结合现有账户服务确定，避免平行存储。

- **能力目录与包版本**：插件/技能稳定 ID、发布者、版本、摘要、资源清单、依赖及所需宿主能力。
- **用户安装与启用**：账户安装哪个版本、启用哪些技能/工具；设备安装通过原有设备适配器处理。
- **服务连接**：与安装分离的账户连接及授权状态；凭据保存在受保护服务端，不能放入技能正文或输入框。
- **会话引用与运行快照**：保存能力 ID、版本、来源及范围；运行固定所用版本，安装更新不修改进行中任务。
- **包和技能草稿**：元数据及版本记录进入 PostgreSQL；包文件、图标及附属资源进入既有对象存储。
- **短任务与缓存**：安装任务、目录读取等利用现有队列/Redis；客户端缓存按账户、宿主和版本区分。
- **实际执行**：指令由现有模型运行按需读取，外部工具经 MCP 适配；云端脚本在受限沙箱执行。

复用 SkillsResourceAdapter 的设计方式，为共享界面提供目录、安装、读取、保存、连接、
启用及试用等动作；适配器返回真实能力，不让 UI 直接写宿主配置或访问任意本机文件。
已有设备适配器不被强制改成账户安装语义，云端账户路由也不能绕过所有权检查。

安装包先校验路径、大小、入口及依赖，再原子生效；脚本和引用文件不因上传而自动执行。
服务端对每次技能读取与工具调用核对账户、版本和可用范围，不能只信任前端勾选状态。
模型可见的工具集合由运行时真实可用性生成，技能指令不能授予未配置的连接或宿主能力。

停用影响后续发现与调用；更新产生新版本。卸载移除后续可用能力，保留既有聊天、产物和
已发送引用记录；当前运行按既有协议明确结束或继续，不能被 UI 重挂载偷偷中断。
撤销连接独立于卸载，用户可以明确知道哪一个账户连接仍然存在。

## 9. 完整实施顺序

### 第一阶段：统一目录、详情及使用入口

先用当前已有的 Product Design、ImageGen 以及设备技能建立真实目录与详情，不展示尚未
接入的第三方“可安装”条目。复用共享导航、条目、菜单、详情阅读及 MentionComposer。
打通“发现 → 查看 → 带引用回到草稿 → 使用现有真实能力”的完整流程，保持现有快捷入口。
桌面、390/440px 手机、浅深主题和加载/空/失败状态同时完成。

### 第二阶段：技能完整生命周期

补齐技能详情文件树、指令与附属资源阅读、上传、编辑、创建、下载、启停和卸载。
CloudChat 接入账户作用域的技能目录和按需读取；已有设备路径继续走设备适配器。
完成版本校验、草稿保护、稳定引用和旧会话可解释性，不能仅交付“能安装”的半条流程。

### 第三阶段：插件包及连接生命周期

实现包含技能/MCP 的能力包与依赖关系、安装更新、管理页和每项能力启用。
完成自定义 MCP、实际需要的认证类型、连接恢复及撤销；选择一个确实可用的外部服务
验证“安装 → 授权 → 会话调用 → 失效后重连 → 卸载/撤销”的闭环，再扩展目录。
不以虚构品牌目录或模拟 OAuth 代替完成。

### 第四阶段：Product Design / ImageGen 与工具工作区深化

将 Product Design 拆成清楚的研究、审查、方向探索、实现、核对和分享工作流，按实际工具
补齐输入、证据与产物。ImageGen 复用真实生图模型设置和图片编辑/成果链路。
插件的交互面板、站点与文件产物接入统一工作区，完成当前会话与资料空间之间的连续使用。
最后在完整生命周期上做性能、可访问性、连接中断及跨账户/设备回归。

## 10. 验收标准

体验验收按用户任务进行，不以组件通过或构建通过代替：

1. 从目录找到能力、看懂用途、安装/连接、回到原草稿、成功调用并查看结果，不丢失已有输入与状态。
2. 技能创建和编辑有真实文件及版本；重载、并发编辑、失败及离开后能恢复，不覆盖其他页面修改。
3. 会话里的引用在重命名、更新、停用或卸载后仍可识别，进行中运行不会因进入设置被重建。
4. 同屏对照参考检查宽度、密度、字重、图标、Tooltip、菜单、焦点及动效；检查完整状态，而非只截图首页。
5. 390/440px、窄桌面、宽桌面、浅深主题均完成相同任务；手机键盘弹出后不遮主操作或产生横向溢出。
6. 键盘可完成搜索、列表选择、菜单操作及引用，IME 输入无误；所有图标按钮有可访问名称。
7. 搜索、切换和刷新不闪空；安装/启用反馈原位发生，缓存不越账户/宿主，重入页面不重复执行写动作。
8. 未配置、授权取消、连接过期、安装失败和未知写结果均有真实恢复路径；没有可点击的空壳功能。
9. 模型执行、MCP 授权、脚本沙箱、图片产物与文件权限分别验收；明确记录真实服务和模拟测试的范围。

## 12. 本轮 Codex 对齐

以当前 Codex/ChatGPT 自定义为参照。上下文侧栏提供插件、技能和已安装插件；搜索已安装插件只过滤该组，不改变目录筛选或当前草稿。宽屏保留共享侧栏和居中的详情；窄屏沿用顶部导航，目录的搜索与操作按可用宽度换行。

插件目录保留公开/个人、安装状态、查看详情与安装操作；工具栏补齐管理已安装插件的快捷入口。独立技能用「已安装」「未安装」分组，不展示包内技能。创建菜单沿用通过聊天、使用编辑器、上传三个入口。每个条目沿用共享行和菜单。

详情将应用、技能、信息分区，应用按真实宿主操作呈现。「创建插件」的应用打开个人插件编辑器，继续使用账户版本校验、离开保护和保存流程。「生成图像」的技能读取器继续提供真实模型配置。应用打开与聊天试用分开，插件内技能按需展开。公开插件的配置仍按账户权限处理；第三方连接只在其真实授权和执行链存在时展示。
