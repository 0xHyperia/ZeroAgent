# ZeroAgent CloudChat 整体设计提案

日期：2026-10-29。状态：用户已选择方向 2，要求接近 ChatGPT 的质感；本轮前端布局已落地并完成视觉核对，
不代表全部 CloudChat 功能或生产验收通过。具体展示决策见 ADR0050，视觉验证见根目录 `design-qa.md`。

## 目标和边界

参考用户提供及已登录 ChatGPT 中实际观察的新对话、工作入口、附件菜单、项目和资料空间，
保留 ZeroAgent 的品牌、共享主题与组件体系。目标是让用户从提问、资料理解和研究，连续完成
分析、文档交付与修改，而不是在首页罗列能力按钮。

继续 ZeroAgent Gateway、Go 唯一编排、PostgreSQL、Redis、对象存储和 E2B 主线。
LibreChat 适用的对话逻辑可按固定来源及许可移植，不复制其整套应用和状态体系。
角色、分组、运营配置管理、运营审计和语音不列入本次范围；已有桌面功能及安全边界保留。

当前预览中的资料侧栏属于第一轮整理。本提案进一步覆盖整个产品的信息架构、主布局、
状态、组件和适配边界；文档中的组件名为建议名称，不声称当前已存在。

## 当前观察与设计结论

本轮参考截图位于 `.codex-artifacts/cloudchat-design-20261029/`。对 ChatGPT 只进行界面观察，
未发送消息、执行工作、上传文件或创建项目。用户原有聊天未作修改。

| 观察步骤 | 实际观察 | ZeroAgent 的设计结论 |
| --- | --- | --- |
| 新对话 | 问候与输入靠近，主要操作集中，周围留白 | 首页以输入为中心，退出四个大卡片与底部输入框分离的结构 |
| 输入菜单 | 上传、资料、项目和工具在统一入口中分组 | 一个能力菜单；不是每新增能力就在标题栏增加按钮 |
| 工作入口 | 较高输入框，项目/文件工具栏，以及少量任务建议 | 同一输入组件可展开上下文和任务入口，不能另造一套草稿状态 |
| 资料空间 | 固定导航、搜索、分类、视图切换、统一列表 | 资料管理应有独立页面，侧栏仅承担当前任务的查看和引用 |
| 创建项目 | 项目是聊天、文件及指令的组织单元 | 项目进入主导航，资料/指令/会话关联有明确入口 |
| 当前 ZeroAgent | 共享侧栏/主题已有基础；空态与输入之间距离大，项目/资料入口较深 | 保留基础组件，重组布局和入口，而非新增独立视觉系统 |

这些观察不构成对 ChatGPT 全部产品能力或 ZeroAgent 可用性的证明；未读取参考账户的资料正文。
截图中的私人会话标题和账户信息不复用为设计稿数据。

## 统一信息架构

用户主要在“对话、项目、资料库”之间切换。设备是执行目标，设置是账户及偏好入口。

| 区域 | 内容 | 入口与返回 |
| --- | --- | --- |
| 对话 | 新对话、最近/置顶会话、会话内搜索 | 主导航；退出其他页面回到原会话和草稿 |
| 项目 | 项目列表、项目内对话、资料与指令 | 侧栏固定分组；项目选择也可从输入框进入 |
| 资料库 | 原始文件、不可变成果版本、已保存的研究来源 | 固定导航；搜索、分类、列表/网格与预览 |
| 当前资源 | 本次会话的附件、成果及引用 | 标题栏/消息引用打开右侧上下文面板 |
| 执行目标 | 云端或明确选择的设备及工作区 | 标题栏独立控件，不混入模型选择或资料分类 |
| 账户与偏好 | 账户、模型设置、外观、显式记忆、退出 | 侧栏底部统一用户菜单，沿用已有设置和生命周期 |

全局窄导航轨是否常驻由视觉方案决定；其作用必须是切换产品区域，不能重复上下文侧栏。
不在主导航出现未实现的团队管理、分享中心、语音或模板编辑器。

ChatGPT 的“聊天/工作”切换可以作为任务入口设计参考，不能照搬成执行授权。
若保留双入口，它们只影响输入提示、上下文工具和结果呈现；仍共用同一会话、草稿及 Run，
不自动开启联网、不改变模型、不获得设备权限。没有实际交互差异时采用单一“新对话”。

## 核心页面

### 新对话

- 问候、输入和两到三个轻量建议构成一个视觉中心，默认在可用画布上半部居中。
- 输入宽度以 720–800px 为主，超宽屏保持可读宽度，不铺满整屏。
- 默认简洁输入，可随内容增高；出现附件/项目时再展示上下文区域。
- 快捷建议只填草稿或打开明确的选择流程，不自动发起模型、研究或付费任务。
- 输入底部集中“添加”、模型/推理档位与发送；语音控件不出现。
- 新对话与已存在对话使用同一个输入组件和草稿所有者，首次发送不丢 IME、选区或附件。

### 已有对话

- 主消息列保持与输入框对齐；用户消息采用轻背景气泡，助手正文保持开放排版。
- Markdown、代码、表格、引用、工具过程和成果卡片按内容类型渲染，不把整段回复套进大卡片。
- 复制、编辑、重生、分支有统一位置；桌面悬停/键盘焦点可见，移动端有可发现的操作入口。
- 思考和工具过程可折叠，最终答案与下载成果始终可达；不能通过折叠隐藏失败或未确认状态。
- 流式输出只在用户仍跟随底部时滚动；向上阅读后显示“回到最新”，不抢位置。
- 若需要消息版本切换，必须由真实父子消息/分支数据驱动。当前另建会话的分支不可伪装成
  已有可切换版本树；模型、附件、项目及原历史保留规则继续由现有服务控制。
- 发送后输入固定底部；生成、停止、断线重连、后台继续和中断有不同状态。

### 资料库

- 采用独立主视图，顶部标题与搜索，随后分类和排序，主体为统一列表或网格。
- 初始分类只提供“全部、文件、成果、来源”。项目是筛选/归属，不与文件类型混为一谈。
- 默认列表列为名称、类型/来源、所属项目或会话、更新时间；窄屏减少列但保留名称和状态。
- 上传是主要创建入口；生成文档、表格、图表等通过新工作流程进入，不伪造已存在的在线编辑器。
- 打开条目时使用统一预览组件；宽屏可并列，窄屏进入单一详情层，返回恢复搜索和滚动位置。
- 文件原件、成果 family/version 和研究快照保持独立身份。成果续改必须明确载入哪个版本。
- 全库搜索需要账户范围的真实服务端查询。仅过滤已加载页时必须明确范围，不假称全库搜索。
- 空列表、搜索无结果、尚未加载、读取失败四种状态分开；错误不呈现为“还没有资料”。
- 不加入尚无服务支持的回收站或恢复承诺；删除与清理保持当前真实语义。

### 项目

- 侧栏可以展开项目及其中会话，项目菜单提供已有能力范围内的新建、改名、设置和归属管理。
- 项目首页包含名称和简述，以及“对话、资料、指令”的明确分区。
- 从项目中开始对话时显示简短上下文标识；更换项目需要明确操作，不能悄悄复制其他项目资料。
- 项目指令和资料保存使用现有版本与归属校验；未保存编辑在关闭/切换时有草稿保护。
- 全局显式记忆与项目指令分开。记忆默认关闭，不自动提取用户隐私，也不扩散到公开研究。

### 资源详情与成果预览

- 侧栏服务于“查看、引用、下载、继续修改”，批量管理回到资料库。
- 同时最多一个资源上下文面板；不同资源用稳定标签切换，切换时保存其选择与浏览位置。
- 宽屏预览宽约 360–440px，必要时可展开；先缩减消息画布，再考虑收起导航。
- 大文档/代码按需加载；图片和图表只使用受控原件/成果下载，保持当前 Blob 与账户守卫。
- 来源显示网页域名、抓取/搜索性质及引用定位；搜索摘要不冒充网页正文。
- 正式 ready 成果才能提供下载；未知执行和未保存路径不能显示为可交付文件。
- HTML/SVG 保留已有安全呈现边界，不为外观预览直接执行模型生成内容。

## 输入、消息和任务的交互状态

| 状态 | 可见反馈 | 可操作内容 | 必须保留 |
| --- | --- | --- | --- |
| 空草稿 | 明确占位与添加入口 | 模型、资料、项目 | 禁止空发送 |
| 输入中 | 稳定编辑区，适度增高 | 发送、附件移除、推理设置 | 中文 IME 与选区，切换资源不丢草稿 |
| 上传/解析 | 附件自身进度和错误 | 删除附件/重试，按能力决定发送 | 不把未解析附件冒充可读 |
| 等待受理/排队 | 一处任务状态 | 查看、允许范围内的取消 | 不重复受理、不清空未受理草稿 |
| 生成中 | 增量正文和明确停止按钮 | 阅读、复制已有内容、切换会话 | 离开不等于取消；不抢滚动 |
| 断线 | 继续读取状态提示 | 重连/核对原任务 | 不自动重发已可能计费操作 |
| 停止待确认 | “正在停止/结果待核对” | 查看已保存内容 | 不提前声称远端已停止 |
| 完成/中断/失败 | 正文、成果与真实终态 | 编辑重试、续改、导出 | 部分输出、原消息和实际错误范围 |

统一能力菜单：上传文件、从资料库添加、选择项目、公开联网研究，以及后端真正支持的工具。
添加文件与选择模型不发出模型调用；公开联网仍保留每次主题确认。
模型和执行目标是独立选择；刷新不能悄悄换分组密钥或回退到本地设备。

Enter 发送，Shift+Enter 换行；中文组合输入期间不发送。
Escape 只关闭最上层浮层并恢复焦点，不作为停止任务的快捷键。
快捷键按应用范围处理，不覆盖浏览器刷新、地址栏或系统组合键。

## 组件化方案

层次为现有 primitives → 共享交互模式 → 产品视图 → 宿主/业务适配器。
优先扩展 `crates/agent-ui`，不再建立一套 Cloud 专属按钮、菜单、对话框和颜色。

| 建议组件/模式 | 职责 | 复用或适配现有模块 |
| --- | --- | --- |
| `AppShell` | 导航、标题栏、主画布与上下文区域 | `AppWorkbenchChrome`、`ApplicationView` |
| `NavigationSidebar` | 项目、最近会话、区域入口与用户菜单 | `ChatHistorySidebar` 及其 rows/types |
| `ConversationLayout` | landing/thread 布局与单一消息列 | 当前共享聊天容器及 Cloud 页面接线 |
| `ConversationHeader` | 标题、项目上下文、执行目标、当前资源 | `ChatHeader`、`ExecutionEnvironmentSwitcher` |
| `ComposerDock` | 同一编辑器的居中/底部排布，不持有第二份草稿 | `ChatComposerBar`、`MentionComposer` |
| `ComposerCapabilityMenu` | 上传、选择资料、项目及工具的分组入口 | 共享 DropdownMenu/Popover/Sheet |
| `ContextChip` / `AttachmentChip` | 项目、附件、版本及处理状态 | `ComposerAttachmentCard` |
| `ModelControls` | 模型、推理与支持参数的统一选择 | 共享模型选择器，保留平台内配置 |
| `MessageContent` / `MessageActions` | 正文类型、引用和一致操作 | `GatewayTranscript`、共享消息与操作组件 |
| `RunStatus` | 等待、生成、重连、中断及停止的真实状态 | 现有 Run 客户端与安全状态映射 |
| `ResourceBrowser` | 搜索、筛选、列表/网格和选择 | 提取现有文件/成果/来源面板的共用模式 |
| `ResourcePreview` | 文件、成果、来源的受控详情 | 现有预览器及账户守卫，支持 page/panel/sheet |
| `ProjectOverview` / `ProjectPicker` | 项目会话、资料及指令入口 | `CloudChatProjectsPanel` 的业务控制器与新视图 |
| `SearchDialog` / `EmptyState` / `ErrorState` | 统一反馈、搜索与恢复 | 共享 Dialog、Skeleton 和 Button |

共享展示组件接收数据、能力与事件，不直接读取账户密钥、不自行调用模型或 Native。
Web/Cloud 适配器继续持有认证、Run、项目及资料客户端；桌面适配器提供原生和设备能力。
不把任意设备 API 或本地文件系统入口传给 Cloud 展示组件。

`ResourceBrowser` 的列表页和侧栏共享查询控制器及元数据投影；展示密度可以变化，
选中、分页、失败恢复和账户清理规则不能另写一套。

`ComposerDock` 在 landing/thread 转换中保持稳定组件身份。草稿、附件、编辑分支和挂起
请求仍由当前单一所有者管理；使用布局状态调整位置，不挂载两个互相同步的编辑器。

## 视觉规范与响应式

- 继续使用 `--background`、`--foreground`、`--muted-foreground`、`--border`、`--sidebar-bg`
  等语义 token；不在页面硬编码第二套浅色/深色颜色。
- 保留 ZeroAgent 银色标志、名称、现有系统中文字体和共享图标风格，不使用 ChatGPT 标志。
- 正文 14–16px，辅助信息 12–13px，页标题 24–28px；代码使用现有等宽字体。
- 图标以 16/18/20px 为主；桌面操作目标至少 32–36px，触屏至少 44px。
- 间距采用共享 4/8/12/16/24/32 等尺度；菜单/条目圆角沿用共享组件。
- 通过对齐、间距和分隔线组织内容，减少嵌套卡片、重阴影和满屏边框。
- 超宽屏增加留白而非拉宽正文；资料库可用更宽的列表画布。
- 大屏可导航/对话/预览并列；中屏优先收起上下文区；小屏一次显示一个主要层级。
- 移动端附件菜单和资料选择使用共享 Sheet；返回恢复原草稿、位置及选择。
- 键盘弹出、安全区、长文件名、长模型名、字体放大及横屏都列为验证项。
- 图标按钮有名称和 tooltip；菜单支持键盘与焦点；状态使用适当 live region；降低动态效果
  时禁用非必要位移动画。不能仅凭设计图宣称无障碍合规。

## 落地和验收顺序

1. 选定统一布局，落实 token/间距/导航、`ConversationLayout` 与单一输入框的双位置布局。
2. 完成项目与会话导航、消息/引用/操作和任务状态；保留全部已有真实能力入口。
3. 建立资料库主视图，并与上下文预览共享组件和控制器；必要查询由服务端按账户实现。
4. 对照实际浏览器检查：空态→输入→附件→生成→编辑/重生→成果→新会话续改→项目接续。
5. 检查双账户、断线/切号、未知提交/取消、资源删除、超长内容、窄屏、深色、键盘与 IME。

设计稿只定义视觉方向。不能把图中的控件或虚构数据算作已实现，不以 UI 截图替代真实模型、
文件内容、E2B 执行或生产能力验收。所选布局已在本地预览落地，未推送或部署；完整 CloudChat 功能仍按实际场景分别验收。
