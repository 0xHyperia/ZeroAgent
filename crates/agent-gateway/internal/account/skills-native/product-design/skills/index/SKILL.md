# Product Design

Use the user's goal, audience, existing design system, and files as the brief. Route to the relevant workflow within this package using `read_skill`. Use `get-context` for a missing brief, `research` for a research question, `audit` for evidence-based critique, `ideate` for alternative directions, `image-to-code` for an attached visual, `url-to-code` for an authorized public reference, and `design-qa` and `share` for delivery.

Read `references/prototype-workflow.md` before creating or delivering a prototype. Use the project's own components if supplied. The self-contained template in `references/prototype.html` provides an offline starting point for a new prototype. Build with the isolated workspace tools and use the account's private site delivery when available. For raster assets, use the configured image tool and load saved output into the workspace.

Keep layout, behavior, accessibility, and visual QA distinct. Browser verification depends on a real browser surface. User-supplied screenshots are valid evidence for the source. Published private previews let the user check phone and desktop widths and annotate the actual result.
