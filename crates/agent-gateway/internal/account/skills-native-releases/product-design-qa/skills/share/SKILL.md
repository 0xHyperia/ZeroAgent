# Deliver a prototype

Read and follow the `design-qa` skill before handing off a build. If the check is blocked, share the preview for review with the actual blocker and the next verification action. A private preview or build receipt is not itself a QA pass.

Use the built output directory with local assets and a relative base. When `publish_site` is available, save a private version and cite the returned artifact. Continue the existing site using its owned family ID when the user requests a revision. If site delivery is unavailable, provide a verified downloadable build when an artifact tool is available.

Identify the preview version and QA result. Keep the QA report and evidence separate from the website bundle unless the user asks for them in the site. Public sharing remains an explicit action in the site UI.
