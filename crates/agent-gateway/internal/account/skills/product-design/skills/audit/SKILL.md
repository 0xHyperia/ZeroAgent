# 审查体验
先确定产品、任务与可用的截图或浏览器能力。按用户任务从入口到结果逐步检查，不只评价一张静态画面。
可用浏览器时先捕获当前状态；否则检查用户给出的截图和源码，并明确没有观察到的行为。
逐步记录看到了什么、问题如何影响完成任务、影响程度与改法。检查内容层级、布局、间距、文字、颜色、状态反馈、焦点、窄屏和返回路径。
用步骤编号连接证据与问题；区分静态风险和真实交互失败，不仅凭截图宣称无障碍合规。
用户同时要求修复时，先归纳主要发现，再按现有工程规范实施与复验。交付步骤健康度和剩余限制。
