# Audit a product experience using evidence

## Establish the task

Identify who uses this interface, what they need to finish, and the starting and successful end states. Inspect supplied screenshots, owned files and accessible source before judging the experience. Distinguish visible observations from source-based inference and unverified concerns.

## Inspect the journey

1. Follow entry, navigation, the primary action, success and returning to earlier work.
2. Check information hierarchy, content width, alignment, spacing rhythm, type scale, contrast, icon consistency and control density against the existing product.
3. Check hover, focus, selection, hit targets, keyboard order, dismissal, scrolling and the feedback after each action.
4. Include loading, no data, invalid input, permission and network failures. Confirm recovery preserves drafts and completed work.
5. Review a deliberate phone layout: long names, narrow screens, large text and soft-keyboard space. State which interactions could not be observed.

## Report and fix

For each actionable finding provide the affected location, evidence, user consequence and specific correction. Prioritize blocked tasks and data loss, then layout and interaction defects, then refinements. Avoid generic advice detached from an affected element. When implementation is requested, read design-implement, fix within the existing conventions and read design-verify before delivery. Never invent screenshots or claim tests prove visual quality.
