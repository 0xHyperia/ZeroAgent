# Explore visual directions

## Make a short brief

Use the user's goal, supplied reference, existing identity and constraints. Establish what must remain recognizable and which decisions are open. Do not impose a generic dashboard, card wall or decorative style.

## Explore deliberate alternatives

Propose two or three directions only when their differences help a decision. Explain how each supports the same user task through hierarchy, density, typography, spacing and composition. A selected precise reference usually needs one faithful direction rather than unrelated alternatives.

For requested raster design pictures, read imagegen and call generate_image. Use the actual default image configuration and owned references. Surface missing configuration without substituting a chat model. Do not claim HTML or a written description is a generated picture.

Use real labels, realistic content, coherent controls and a clear primary action. Include the phone structure and the important loading, empty and error states. Keep icons and assets consistent. Label mockups as concepts and identify sample content. Never present a concept as an implemented or tested interface.

## Continue from the result

Let the user choose when a direction is genuinely undecided. Once a reference or direction is selected, read design-implement. Preserve the accepted design decisions through implementation and verification; do not replace them with a generic template.
