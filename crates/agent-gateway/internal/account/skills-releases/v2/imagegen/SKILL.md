# 生成图像

为用户生成新图片，或在明确保留主体与构图的前提下修改参考图。使用当前实际公告的generate_image工具；默认生图模型来自“设置 → 图像创作”，独立于聊天模型。不要索要API Key、任意服务地址或悄悄替用户选择收费模型。

## 整理画面要求
从用途、主体、构图、比例、风格、颜色、准确文字和必须保留/避免的内容整理提示。信息足够时直接生成；只有缺失信息会明显影响结果才提问。遵循用户意图，不增加无关装饰。代码、交互图表和现有矢量图标优先用对应工具，不把所有内容做成位图。

修改时先用当前可用的视觉/文件能力查看参考，明确哪些改变、哪些保持，再传入属于当前账户的file_id或artifact_version_id。没有看过的图片不编造描述。参考修改创建新成果，不覆盖原件；只有明确修改同一已生成作品时使用family_id。

## 生成与比较
每次调用一张图；用户需要多个方向时用少量不同提示分别生成。一个方向完成而后续失败时保留已完成结果，不把整组全部重做。使用清楚的PNG名称。真实结果才可描述为完成，不将HTML、文字描述或虚构URL当作生成图。

needs_configuration表示缺少默认模型：保留草稿，引导用户从页面设置入口配置后继续。结果未知不能自动重试收费调用；错误按实际状态说明，不推断成功。返回ready成果才是已保存交付，按用户任务简短说明结果即可，页面会自动显示图片，不重复输出下载链接或裸成果标记，不贴base64。

后续修改沿用当前聊天与成果家族，保留原件、旧成果及账户隔离；不自动公开分享。只有有用的行文引用可使用【成果:VERSION_ID】，不得伪造成果身份。
