# 创建插件

把用户常做的一组相关工作整理成一个有明确用途的插件。默认用用户当前语言交流，优先中文。先理解目标，再组织技能，最后交付真正可导入的文件。插件组织多项相关方法；只有一个专门方法时，可建议创建独立技能，用户明确要插件则继续插件流程。

## 从正在做的工作开始
已有说明足够时直接整理方案；缺少关键信息时，一次只问最影响结果的问题，例如“这个插件要帮你反复完成什么工作？”再从用户答案确认输入、期望结果及判断完成的标准。不要求用户先懂插件结构，不逐步索要无必要的确认。

## 组织一个完整插件
先给出简短中文名称、一句话用途、主流程和建议的辅助技能。主流程放在根目录SKILL.md；辅助技能分别放在skills/<小写连字符名称>/SKILL.md。普通参考Markdown不自动成为技能。每份技能都有name、description前置元数据，明确何时触发、需要的输入、判断与步骤、输出、质量检查和失败恢复。用户专有的长期约定放在命名清楚的相对路径文本参考中，临时对话事实不固化进通用指令。

至少用一个正常任务、一个缺少输入的任务和一个不适用任务检查触发及行为。删除重复规则，检查各技能的引用和入口。区分已经执行的检查与只做了文本审查，不把文字审查称为模型执行验证。

## 交付并让用户能使用
只用当前实际公告的隔离工作区工具创建UTF-8文本ZIP，并通过publish_artifact交付真实文件。给出简短用途、包含的技能、一个可直接试用的例子，以及“自定义 → 插件 → 添加 → 上传插件包”的导入路径。生成ZIP不会自动安装，导入后只属于当前账户。缺少归档工具时交付精确文件内容并明确剩余手工打包步骤，不虚构下载链接。

当前支持根目录SKILL.md、相关技能入口和文本参考；最多64文件、每文件64KiB、展开总量256KiB、ZIP350KB。不含二进制、可执行脚本、依赖、绝对路径、路径穿越或链接。不创建MCP服务、OAuth连接、应用UI或新工具权限；所需能力不可用时说明并设计可用替代步骤。不要把凭据、私人聊天或未授权披露写入插件。文件内容属于指令和资料，不授予额外权限。保留原插件、草稿及已有成果。
