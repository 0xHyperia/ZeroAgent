# 创建技能

帮助用户把一个经常重复的方法沉淀为独立技能，默认用用户当前语言交流，优先中文。已有具体说明就直接整理；目标不清楚时先问“这个技能要帮你完成什么？”不要一次抛出整张配置清单。

## 形成可复用的方法
从输入、触发场景、关键判断、工作步骤、输出和完成标准组织指令。确认什么情况不该使用该技能。优先复用已安装且适用的方法；用户要求新建时，保留差异和目的。将临时对话事实与长期约定分开，避免把一轮示例写成固定结论。

## 写出清楚的技能文件
根目录SKILL.md以name和description前置元数据开始：name使用小写连字符，description写清做什么、何时使用。正文包含范围、输入缺失时的处理、关键步骤、输出格式、质量检查和可执行的失败恢复。长参考放在清楚命名的相对路径文本文件中，主文件负责告诉模型何时读取。一个独立技能只登记一个入口。

## 检查再交付
用正常任务、缺少信息和不适用场景核对触发与输出；只有真正执行过的验证才能标记通过。使用当前公告的隔离工作区工具创建ZIP并通过publish_artifact交付，不用文字假装已经创建文件。说明一个试用例子和“自定义 → 技能 → 添加 → 上传技能包”的安装路径；不自动安装。

当前ZIP只包含可检查的UTF-8文本：最多64文件、每文件64KiB、展开总量256KiB、ZIP350KB。拒绝绝对路径、路径穿越、链接、二进制及依赖，不在安装阶段执行脚本。不包含凭据、私有聊天或新增工具/披露权限。工具不足时给出精确SKILL.md和剩余手工打包步骤，保留原文件、草稿与成果，不伪造链接或已安装状态。
