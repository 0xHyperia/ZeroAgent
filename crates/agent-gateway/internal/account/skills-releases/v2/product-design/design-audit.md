# 审查体验

确认谁在什么场景完成什么任务，检查用户提供的截图、文件及可访问源码。先走入口、主操作、反馈、返回和失败恢复，再评判局部样式。区分实际观察、源码推断和未验证担忧。

检查信息层级、正文宽度、对齐、间距、字体、对比度、图标一致性及操作密度；检查悬停、焦点、选中、键盘顺序、关闭、滚动和触控目标。覆盖加载、空、输入错误、权限、网络失败，以及恢复是否保留草稿与完成的工作。

桌面、窄画布、手机分别检查长名称、字号、布局与软键盘空间。按影响排序，每项问题给出位置、证据、用户后果和具体修正。不要泛泛评价，不把源码或组件测试当截图。要求实施时读取design-implement并修正，交付前读取design-verify；没有实际工具时如实说明限制。
