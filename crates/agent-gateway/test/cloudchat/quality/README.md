# Content quality inputs

`generate_inputs.py` produces synthetic PDF/DOCX/CSV/XLSX/PNG/code inputs and an
independent `expected.json`. It uses only the pinned template's installed
libraries, writes a new directory and refuses to overwrite earlier evidence.
Generation never calls a model, E2B, search, storage or an external account.

Run the following tasks through the production Web build when dedicated live
resources and a spending budget are authorized. Preserve original inputs,
all user instructions, actual usage, output files and failures for human review.

1. Upload the meeting DOCX. Request a Chinese work plan, then shorten it and
   change the audience. Budget/date/unknown customer count must remain correct.
   It must not send email or publish. Refresh and export the complete history.
2. Compare both PDFs. Require page citations for the two changed limits and
   explicitly identify the unchanged durability policy. Open each citation.
   Separately upload the resource-table PNG: read all three Chinese row labels
   and amounts, identify **设计** as the largest and total **124.75**. The
   corresponding scanned PDF has no text layer; it must accurately report its
   extraction limit. A blank/tiny PNG or matching upload hash cannot establish
   visual understanding.
3. Analyze CSV and XLSX. Deduplicate by order ID, report the missing quantity,
   include the refund and obtain **44.25**. Deliver a cleaned sheet and chart.
   Change the rule to exclude refunds; recomputation must obtain **49.50**.
4. After the original workspace has ended, load that saved result in a new chat,
   revise it and download v2. Re-download v1 and compare its original SHA.
5. Upload the code ZIP. Identify the defect, fix it, actually run both unittest
   cases and deliver source plus a reviewable diff. A claim that tests passed
   without a tool execution receipt does not pass.
6. In two accounts/browser sessions, check project/memory scope, reload,
   disconnect and sign-out. Use only synthetic private markers for leakage tests.
7. Research a question with an explicit date boundary using approved public
   topics. Independently open original sources and check each factual claim;
   distinguish search snippets, fetched text and inference. This task cannot be
   accepted using a fixed fake search response.

Pass requires factual correctness, usable files, preserved revision requirements,
accurate progress/failure feedback, owned resources and reproducible receipts.
Use a short review note per criterion; do not replace failures with an average
score. These tasks are a finite baseline, not a requirement to copy every
competitor feature. Generated inputs and local parser success are not proof of
model quality or remote service acceptance.
